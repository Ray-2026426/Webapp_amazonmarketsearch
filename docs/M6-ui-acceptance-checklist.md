> 用途：你不必读代码，照着这份清单点一遍，就能判断"实现和线框图/PRD 是不是一致"。

> 对照物：`docs/ui-wireframes.html`（主流程 8 屏）、`docs/ui-wireframes-l3.html`（二级页 23 屏）、`docs/amazon-market-research-prd-v2.md`（V2.9）。

## 0. 先确认你在看哪一份（最容易误判的一步）

| 我要验的东西 | 该打开哪里 | 为什么 |
| --- | --- | --- |
| 本机开发 | `http://localhost:3000` | dev server 的 HMR 是**关闭**的 → 改完代码必须**硬刷新**（Ctrl+Shift+R） |
| 线上预览（phase-0） | Vercel 的 Preview 部署 | push 到 `phase-0` 会自动出预览；**别用 production 域名**验新功能 |
| 管理员功能 | 同上，且 `ADMIN_EMAILS` 必须勾了**对应环境**（Preview/Production 是两套变量） | main=Production 变量，其他分支=Preview 变量 |

三个已知的"看起来像 bug、其实不是"：
1. **本机**管理员后台显示「Supabase 未配置 / 不可达」→ 本机没有 `SUPABASE_SERVICE_ROLE_KEY`，是缺少服务端密钥，不是权限问题。线上才看得到真实用量/审计。
2. 未登录时 `/api/data/status` 返回 401 → 数据池只对登录用户开；游客会被明确引导到示例数据。
3. 线上改了环境变量后功能没变 → Vercel 环境变量是**部署时快照**，必须 Redeploy 一次；改完用户刷新页面即可，**不用退出重登**。
4. 管理员后台出现**琥珀色「数据库还没迁移」**提示 → 这不是故障：它现在会**逐表列出**缺哪张、必建还是可选、缺了影响什么，并提供「**一键复制建表 SQL**」；粘到 Supabase → SQL Editor 执行即可（幂等、不破坏数据）。**不跑也能用** —— 只有 `projects` / `project_members` 缺才真的存不下，其余是"用量统计/审计/缓存持久化/资产上传"缺失或退化。
5. 数据库报权限错误（`42501` / permission denied / RLS）时**不会**被当成缺表（跑迁移解决不了），会明确说是权限问题。

## 1. 主流程 8 屏（10 分钟走完）

### 屏 1 · 全局壳 + 项目中心
- [ ] 左侧栏：**项目中心**，其下缩进子分组 **市场大盘 → 竞品明细 → 用户洞察 → 关键词分析 → 利润计算器**（2026-09 用户指示恢复，**与线框图第 1 屏冲突**，属"用户指示的临时回退"，见 PRD §15.18）。
- [ ] 项目列表是**少量宽卡**，每张卡上有：结论 + 下一步 + 主操作按钮。
- [ ] 新建项目：品类名 / 关键词 / ASIN **三选一** + 站点 + 目标，缺哪个都建不出来。
- [ ] **项目卡上不再有「归档 / 恢复」按钮，也没有「已归档」筛选**（该功能 2026-09 按用户要求删除，见 PRD §15.20）；要清理列表用「删除」（有二次确认）。历史上被归档过的项目应当**重新出现在列表里**（不再被过滤掉）。

### 屏 2 · 项目内骨架
- [ ] 顶部步骤条是 **看用户 → 看市场 → 看竞对 → 看自己 → 看机会 → 报告**，能来回切且不丢数据。
- [ ] 有 **一键向导**，也有**每一步的局部重跑**（不是只能全量重跑）。
- [ ] **右侧「决策草稿」栏在任意一个看里都常驻**（这是本轮修的核心 IA 变化）：切到看市场/看竞对/看自己，它都还在，里面有 进度 / 下一步 / 未满足需求 / 缺什么 / 证据 / 快照。
- [ ] 看机会里有 **2×2 优先级矩阵**。

### 屏 3 · 看用户
- [ ] 四块齐全且顺序是 **① 搜索路径 → ② 搜索偏好 → ③ 需求分类 → ④ 细分标准**。
- [ ] 每块右上角有「查看详情」→ 打开**全屏二级页**（有「← 返回」，Esc 也能关）。
- [ ] ④ 细分标准：勾选的需求域里**第一个是主标准**，能填理由；不勾也能用（看市场会退回默认三方案）。
- [ ] 每个需求都能点开看证据：关键词 / 评论原文 / 覆盖 ASIN / 证据强度（**不是** AI 打的分）。

### 屏 4 · 看市场
- [ ] 第一步是**选细分方案（选择题）**，不是直接甩一堆图表。
- [ ] 第二步是**细分机会池排行**，每张卡有机会分与趋势/体量/竞争拆解。
- [ ] 每张细分卡与方案卡里的每个细分都有独立的 **「查看完整大盘 →」**；点开后大盘顶部出现**「当前：X（来自看市场）」**筛选横幅 + **「切到全市场（清除筛选）」**。
- [ ] 第三步能**选定目标细分**，并且它会被喂给看竞对（选完后去看竞对，样本池应围绕该细分）。
- [ ] 方案 A 是"按需求域切"：若看用户 ④ 设了主标准，方案 A 会优先按它切（而不是各切各的）。

### 屏 5 · 看竞对
- [ ] 挑出的竞对 **≥3**，并标明**头部 / 跟随者 / 新人**三种角色（各自的判定依据可见）。
- [ ] **三列对比**：每一列一个竞对，字段齐全且**标了来源**（缺失的字段写「未抓取」，不能留白）。
- [ ] 每个竞对下面都有**三块分析**：用户画像 / 痛点未满足矩阵 / 需求满足矩阵。
- [ ] 每张竞对卡有 **换人**（带"为什么它也行"的理由候选）。
- [ ] 结论是**赢的路径**，且按固定顺序判：人无我有 → 人有我优 → 人优我廉 → 无赢面（每条的判定依据可见）。
- [ ] 下钻一行四个入口 **⑦⑧⑨⑩**：⑦/⑧ 落到竞品明细的 **Listing 详情页**，⑨ 落到 **流量**视图，⑩ 打开 **评论 VOC / 用户洞察**（ASIN 自动带入，toast 会写明落到哪个视图）。

### 屏 6 · 看自己（2026-09 按用户要求改：背景信息 + 3 个拍板问题）
- [ ] 顶部标题是「看自己 · 背景信息 + 3 个拍板问题」，右侧显示 **已答 x/3**。
- [ ] **背景信息（只读摘要）**：显示「背景信息完整度 7/29」+ 7 个分组，每组一行写清"影响五看里的哪个判断"；点组名才展开已填值；这**不是表单**，补全要去「设置 → 背景信息」。
- [ ] **不再有 42 项四态网格**（也没有 20 项背景库四态网格）：页面上找不到逐项点"已具备/部分具备/不具备/待确认"的长列表。
- [ ] **能力推导**：一行汇总「已具备 x / 部分具备 y / 不具备 z / 判断不了 w」；点「展开看每一条怎么推的」能看到每条能力的规则编号与依据（例如"背景信息「广告投放」= 无 + 团队 1-2 人 → 判定为不具备"）。
- [ ] **逐条覆盖**：改某一条能力会显示「已人工覆盖」，点「恢复推导」回到推导结论；AI 不会改这些结论。
- [ ] **只有 3 个问题**：① 最低毛利率（下拉区间）② 止损条件（下拉 + 可补充一句话）③ 必须满足的进入条件（多选）。
- [ ] 每道题都能看「为什么问：…」（依据），每个选项都带「为什么不」；Q3 每个条件旁显示「你现在：…」，**这个状态是由背景信息算出来的**（例如背景里认证=暂无 → "认证齐备"显示不具备）。
- [ ] 有**适配度**与**硬约束**；硬约束触发时明写 **「不可直接进入」**（例如：第 1 题选"还没定"，或 Q3 勾了"认证齐备"而背景里认证=暂无）。
- [ ] **背景信息会实时生效**：在设置里补一项背景（如把认证选上 CE/FCC），回到看自己不需要手工刷新，推导结论与 Q3 的「你现在：…」会立刻更新。
- [ ] 改答案会**联动**看机会（硬约束红条）与看竞对（赢的路径判定；第 1 题选的红线会写进毛利红线口径）。
- [ ] 旧版数据不丢：以前 42 项里标过"不具备/部分具备"的决策边界记录，会以「旧版 42 项里的决策边界记录」显示，并**继续触发硬约束**。

### 屏 7 · 看机会
- [ ] 顶部 **Go / No-Go 汇总** + 一句话理由。
- [ ] **零机会也是合法结论**：没有卡时不会假装有结论，而是给"已判断无机会 / 证据不足"并要求人工确认。
- [ ] 每张机会卡有：**评分拆解（五维）**、证据引用、推理、**反证**、路线图（先做/后做）、前置资源（含 `[缺口]`）、**三类控制点**（准入/过程/止损）。
- [ ] **全局先后建议**区块：给出排序 + 每条的理由 + 已拍板标记，并明写"**先做哪个由你拍板**"。
- [ ] 硬约束未通过的卡：**卡顶红条**，且进入方式最高只能"验证后进入"。

### 屏 8 · 导出决策包
- [ ] 导出 HTML 与 MD，**两份结构一致**，顺序都是：**首页只放结论 → §1 研究目标 → §2 用户需求 → §3 市场细分 → §4 竞品缺口 → §5 自身适配 → §6 机会结论 → §7 证据索引与口径**。
- [ ] **首页只有结论**（项目/站点/生成时间、机会 N｜暂缓 N｜证据 M 条｜已拍板 D 张、Go/No-Go 一句话 + 分析口径），没有长篇分析。
- [ ] §7 是**独立章节**：证据逐条编号（哪一看 / 类型 / sourceRef / 摘要 / 时间）+ 口径（权重 25/25/25/15/10、AI 只解释不改分、"未提供/未抓取"约定、哪些结论经人工确认）。
- [ ] 故意缺数据时（比如没选目标细分），对应位置写 **「未提供」**，而不是编一个数或留空。

## 1.9 AI 配置（2026-09 按用户要求再简化：无步骤编号、按钮在模型名之前）

- [ ] 设置 → API 与模型：**没有 ①②③ 步骤编号**，就是「选 AI 供应商 → API Key → 模型」三块 + 一个折叠的「高级设置」。
- [ ] 按钮顺序：**「获取模型」与「验证」都在"模型"下面、下拉框之前**（用户要求"验证按钮放在模型名的前面"）；未填 Key 时两个按钮都禁用并提示先填 Key。
- [ ] 填好 Key 点「获取模型」：列出该 Key 的可用模型（一片标签），**点一个即选中**并进入「当前使用」下拉；另有「全部加入可选列表」。
- [ ] 拉不到时（很多中转站不提供 `/models`）提示能看懂；**「手动添加模型名」已按用户要求删除**，不要再出现。
- [ ] **默认请求地址=官方地址**：DeepSeek 走 `api.deepseek.com`（不再指向 `openrouter.fans`）；页面上没有"官方地址 / 本站默认转发到 / 本次实际请求"三行大字。
- [ ] 展开「高级设置」才有：请求地址输入框、「恢复默认（清空）」、「浏览器直连」开关。
- [ ] 真接一个中转跑一次 AI（如看用户 → AI 分析）：能出结果即为通；地址填错时报错能看懂（"返回的是网页而不是 API 数据"这类），而不是 JSON 解析错误。
- [ ] 安全底线（可自查）：登出后自定义地址不可用（401）；地址填 `http://127.0.0.1:8080/v1` 被拒（提示"禁止访问内网/环回/元数据地址"）。
- [ ] 设置 → **诊断** 顶部能看到「前端构建：…」；打开页面时控制台也打印同一句（用来确认"你手上是哪次构建"）。

## 1.10 MCP 配置（名称 / URL / Key / 验证 —— 2026-09 起**所有用户都能填自己的 Key**）

- [ ] 设置 → MCP 数据：每个数据源的**一行**里有 种类标签 + 名称（可改）+ 启用 + **验证**按钮（结果直接显示"可用 / 不可用"）。
- [ ] **每个数据源都有 Key 输入框**（密码框、统一渲染，不许按供应商区别对待）；已填时**掩码显示**（`sk-1…ab12`）+「清除本机密钥」；旁边一行 ≤30 字提示说明"自己的 Key 只存本机"。
- [ ] ⚠️ **留空会怎样？当前代码的实际政策**（2026-09 由并行的 Codex 代理提交 `16fb47a` 改成）是：
      **没有用户 Key 就明确报「请填写你自己的 Key」，不再回退平台默认 Key。**
      这与 PRD §15.26 记录的"留空 = 用平台 Key（团队共享）"**不一致** —— 两项待你拍板：
      ① 是否保留平台兜底；② 是否要把 Key 按账号存到服务端（跨设备跟随账号）。
- [ ] 「验证」按来源如实反馈，按钮/toast 要说明这次用的是哪一个（不再出现"请先填写密钥"这种死路）。
- [ ] 安全底线（可自查）：自己的 Key **不进 URL**（只在请求体）、**不写库**（保存配置时网络请求数为 0）、**不写日志**、**不出现在任何接口响应里**；上游报错若回显了 Key，必须被脱敏后才显示。
- [ ] 管理员后台「用量统计」能**按 Key 来源分账**（平台 / 用户自带），且**只记标签不记 Key**。
- [ ] 「自定义 MCP 地址」在平台供应商那里收在「高级」折叠，默认留空即走应用内安全代理。

## 1.11 角标规范（2026-09 新增：说明文字不再平铺）

- [ ] 凡是**解释性**的长说明（≥2 行 / ≥60 汉字），现在都应是一个 **ⓘ 角标**：**悬浮显示、点击固定、再点关闭、Esc 关闭、Tab 可聚焦、点外部关闭**。
- [ ] 角标是**默认不占位**的一颗小图标（内联在标题/表头后），正文只留 ≤20 字摘要 —— 不应出现"为了放说明而撑高一块区域"。
- [ ] **关键口径不许藏进角标**（这是硬规矩，与上面相反的另一半）：硬约束/合规与安全口径、决策边界、会改变结论解读的口径、禁止性规则、错误与空状态、下一步动作 —— **必须留在正文**。自查几处典型：看机会的「零机会只有两种写法」、红条「不可直接进入」、管理员后台的「密钥只在服务端」、VOC 标签的「需同时满足（且）」。
- [ ] 用户点名的那处：**团队空间顶部的「角色口径 ⓘ」**（原来是 4 行角色映射 + 一段说明 ≈212 字，现在正文只剩"角色口径"四个字）。
- [ ] 角标在**窄容器**里不破版（表头、卡片标题内也正常，不被 `overflow` 裁掉、贴边时自动翻转/夹取）。
- [ ] 不再存在"各写各的手搓角标"（历史上 MetricCard / BrandLeaderboard / MarketConcentrationChart / CompetitorHub 各有一份，已统一）。

## 1.12 竞品整套图（2026-09 新增口径：默认抓 Listing 图库，默认不含 A+）

- [ ] 看竞对页的竞对卡里能看到「**整套图（Listing 图库：主图 + 附图）**」区块，逐张缩略图，而不是只有一张首图。
- [ ] 默认口径：**图库第 1-9 张（上限 9，依据 Amazon 详情页图位上限）、默认不抓 A+ 模块图**；要 A+ 需显式开开关（默认关）。
- [ ] 超出上限会**截断并如实记数**（界面/数据里能看到"被截断"，不是悄悄丢）。
- [ ] **成本不变**：整套图来自**同一次** `asin_listing` 调用（不是每张图一次调用）；用量记账与成本表没有新增项。
- [ ] 老快照（只有首图）**不会变成空**：会退化成"只有那一张"。

## 2. 二级页 23 屏（抽查即可）
- [ ] **①②③④** 从看用户各卡「查看详情」进入；**⑪⑫** 从看自己进入（⑫ 的入口文案是「查看本题依据」）；**⑬** 每张机会卡右下「查看详情」**或点卡片标题**；**⑭** 路线图区块「查看详情」。

## 3. 商用口径（PRD §8 / §11）—— 这些能用"查数字"验，不靠感觉

- [ ] 评分权重就是 **25 / 25 / 25 / 15 / 10**（需求强度 / 市场机会 / 竞品缺口 / 自身适配 / 证据可信度）；未选目标细分时"市场机会"取全市场分 **×0.6**。
- [ ] **数据覆盖度独立展示，不进 100 分**；缺失维度**从分母移除**（不会因为缺数据把分数拉低成"看起来没机会"）。
- [ ] **AI 只解释、不改分**：重跑 AI 后，五维分数与总分的口径不变；已确认/已拍板的卡不会被 AI 覆盖。
- [ ] 每个数字都能**追到证据**（点开看是谁的关键词/哪条评论/哪个 ASIN 的缺口）。
- [ ] 数据池只对**登录用户**开；浏览器里**看不到任何密钥**（设置里只有"已配置 + 指纹"）；管理员后台只回状态不回密钥值。
- [ ] 同一 ASIN 连续抓两次，第二次显示**缓存命中**、成本为 0；管理员能设**月配额**，超额返回 429。
- [ ] 管理员能回答"这个月钱花在哪"（按工具/项目/用户看用量与成本）。
