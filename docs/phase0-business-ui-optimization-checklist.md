# Phase 0 业务与 UI 优化 PRD（问答校准版）

> 核心目标：让产品经理、选品人员或老板在约 30 分钟内完成一个品类的初步拆解，明确回答“这个品类有没有机会；如果有，具体是什么机会；为什么”，并导出一份图文并茂、易于同事查阅和审核的 HTML 报告。

> 实施状态（2026-08-30）：本 PRD 的 Phase 0 主闭环已在 `phase-0` 分支落地，包括项目中心、项目结论、需求分类、细分大盘二级页、竞对需求矩阵、账号背景与品类问题、0–N 机会复核、四个 Prompt 预设和 HTML 报告。下文“问题/当前”保留的是改造前诊断，用于解释设计取舍，不代表现在仍未实现。规则层已由 `tests/progress.test.ts` 覆盖，并通过 `npm test`、`npm run lint`、`npm run build`。

## 已确认的产品定义

| 项目 | 已确认结论 |
| --- | --- |
| 核心用户 | 产品经理、选品人员、老板 |
| 使用场景 | 新品立项、新品开发、寻找新类目、日常市场监控 |
| 项目数量 | 通常每月研究 1–2 个，偏深度管理，不是大批量项目管理 |
| 最小建项信息 | 研究目标、亚马逊站点 |
| 推荐路径 | 看用户 → 看市场 → 看竞对 → 看自己 → 看机会；其中“看用户”贯穿始终 |
| 机会定义 A | 市场水涨船高、需求增长或供不应求形成的市场型机会 |
| 机会定义 B | 竞品未完全满足用户需求形成的缺口型机会，缺口可能来自功能、价格、体验或其他因素 |
| 最终结果 | 允许输出 0–N 个机会；没有充分证据就输出 0，并说明无机会或证据不足的原因 |
| 机会生成 | AI 综合五看生成，允许用户确认、编辑、调整；需要预设可编辑 Prompt 并接入 Prompt 管理中心 |
| 机会证据 | 每张机会卡必须能进入二级页，查看原始证据和 AI 推理过程 |
| 当前范围 | 暂不管理打样、访谈、广告测试、负责人和截止时间等后续验证执行流程 |
| 最终交付 | 图文并茂、易阅读、可发送给同事或审核者的 HTML 报告 |

## 与上一版相比的关键修正

- 删除“多项目决策队列、到期任务、验证任务管理”等过度设计；当前每月只有 1–2 个深度项目，项目中心应更简单。
- “看用户”不再只是五个并列模块之一，而是定义细分市场、选择竞品、判断竞品缺口和生成机会的贯穿主线。
- “看市场”不是一张泛市场摘要，而是先展示需求细分市场机会评分，再进入每个细分市场的完整市场大盘二级页。
- “看自己”不再让用户重复填写通用背景，而是自动读取账号背景，并由 AI 针对当前品类提出少量引导问题。
- “看机会”不承担后续项目执行，只负责严格识别机会、展示证据与推理、支持人工复核，以及输出 HTML 审核报告。

## 1. P0｜将项目中心改成适合 1–2 个深度项目的简洁入口

### 问题

当前项目中心同时展示搜索、筛选、云同步诊断、三列项目卡、五看未完成总数和固定“今日建议”，更像管理大量项目的后台。真实用户每月通常只研究 1–2 个品类，这些全局统计不能帮助用户更快得到品类结论，反而增加首屏噪声。

项目卡目前主要展示站点、负责人、更新时间和五个状态点，但用户真正关心的是：这个品类研究到哪了、当前结论是什么、下一步点哪里。

### 方案

项目中心采用“少量宽卡 + 最近项目优先”的布局，不做复杂驾驶舱：

- 顶部只保留标题、搜索、新建项目和轻量同步状态。站点、归档等低频筛选放入“筛选”菜单。
- 活跃项目使用单列或两列宽卡，最多优先展示最近 3 个；归档项目折叠在下方。
- 每张项目卡固定展示：项目名称、研究目标、站点、当前阶段、最近一次业务结论、完成度、更新时间和“继续研究”按钮。
- 如果尚未产生业务结论，就显示缺口，例如“尚未完成需求分类”“尚未选择目标细分市场”，不能只显示一个灰色状态点。
- 新建项目只要求“研究目标”和“站点”；名称可由用户填写，也可根据研究目标自动建议。核心关键词、ASIN 等资料进入项目后再补充。
- 新建成功后仍停留在项目中心，但新卡置顶高亮，并出现明确按钮“开始看用户”。
- 云同步正常时仅显示图标；失败时才展开提示，不能长期占据首屏整行。

### 推荐卡片排版

```text
项目名称                    研究中 · 看市场
US｜研究目标：判断薄枕品类是否值得进入

当前结论：已识别 4 类需求，等待选择目标细分市场
进度：3/5 个视角已有结论        更新于 2 小时前

[继续研究]                                  [更多]
```

### 验收清单

- [ ] 用户进入项目中心后 3 秒内能找到最近项目并继续研究。
- [ ] 项目卡直接展示业务结论或缺失原因，不只展示五个颜色状态点。
- [ ] 新建项目必填项只有研究目标和站点；其他信息不会阻塞开始研究。
- [ ] 新项目创建后无需搜索或二次定位即可进入“看用户”。
- [ ] 正常同步状态不占用主要视觉空间。

## 2. P0｜重构五看信息架构：看用户贯穿主线，细节全部进入项目内二级页

### 问题

当前层级是“项目概览 → 五看 Tab → 摘要卡 → 跳到全局分析工具”。项目概览主要重复完成度，各看又重复标题、状态和样本数，真正的细节散落在市场大盘、关键词、VOC、竞品分析等全局工具中，用户容易失去项目上下文。

五看在业务上并非五个完全独立的模块。“看用户”产生的需求分类决定后续如何划分细分市场；看竞对时也必须回到用户需求，判断竞品满足了谁、满足了什么、哪里没有满足。因此，页面不能只靠五个平级标签表达业务关系。

### 方案

项目内部采用三级结构：

- 一级页“项目结论”：展示目前有没有机会、当前需求分类、目标细分市场、关键竞品、自身适配和下一步。
- 二级页“五看”：看用户、看市场、看竞对、看自己、看机会各自承载完整业务结论和主要分析。
- 三级详情：关键词原表、评论原文、单个细分市场大盘、单个 ASIN、机会原始证据等，用页内 Tab、抽屉或弹窗展开。

推荐流程仍为：

`看用户 → 看市场 → 看竞对 → 看自己 → 看机会`

但每个后续页面顶部固定显示“当前需求主线”：

`需求分类 / 目标用户 / 使用场景 / JTBD / 当前替代方案`

用户可以随时回到看用户修改需求分类。修改后，依赖该分类的细分市场、竞品判断和机会卡应显示“需求已更新，建议复核”，而不是静默保留旧结论。

### 项目一级页布局

- 顶部：一句当前判断，例如“已识别两个候选机会，但竞品缺口证据不足”。
- 中部：需求主线和 0–N 个候选机会的简要卡片。
- 下部：五看结论卡。每张只显示“一句结论、两条证据、一个缺口、查看详情”。
- 固定下一步：根据缺失证据推荐一个动作，例如“选择要深入的细分市场”。

### 导航规则

- 面包屑统一为“项目中心 / 项目名 / 看市场 / 细分市场名”。
- 不再使用“回到市场大盘细节”“返回竞品分析细节”等方向不清的文案；统一使用“查看详细分析”和“返回看市场”。
- 从三级详情返回时，项目、当前需求、所选细分市场、筛选条件和滚动位置必须保留。
- 全局工具能力可以继续复用，但视觉上必须属于当前项目和当前二级页，不能让用户感觉跳到了另一个产品。

### 验收清单

- [ ] 项目一级页能回答当前有没有机会、证据够不够、下一步是什么。
- [ ] 看市场、看竞对、看自己和看机会始终显示它们正在验证的用户需求。
- [ ] 每个五看模块只有一个明确二级入口，不再出现摘要页和全局工具页职责重叠。
- [ ] 修改需求分类后，受影响的后续结论会明确提示复核。
- [ ] 页面首屏只有一个主标题，不再连续出现全局标题、项目标题和摘要标题。

## 3. P0｜按真实业务重新定义五看内容与二级页面

### 看用户：形成后续分析的需求分类标准

看用户首页不能以关键词数量或评论数量为核心，而应直接呈现：

- 需求分类：功能需求、价格需求、体验需求、场景需求或其他由数据归纳出的需求组。
- 每类需求对应的用户画像、场景、JTBD、决策路径和当前替代方案。
- 需求强度：出现频率、严重程度、付费意愿、跨关键词/VOC 的一致性。
- 已满足与未满足部分，明确哪些只是普通抱怨，哪些可能形成后续细分市场。
- 每类需求提供“作为细分市场标准”开关或确认动作，确认后传递给看市场。

关键词分析、搜索意图、完整 JTBD、评论情绪、评论原文、用户旅程和 AI 报告放入三级详情。AI 可以先自动分类，用户必须能够合并、拆分、重命名和排除错误分类。

### 看市场：需求细分评分 + 每个细分市场的完整大盘二级页

看市场一级内容是所有需求细分市场的机会评分列表，而不是泛品类总览。每张细分卡至少显示：

- 细分市场名称及其来源需求。
- 机会评分和证据可信度。
- 市场体量、趋势、供需状态、品牌/ASIN 集中度、价格带空档、新品表现。
- 市场型机会判断：是否存在“水涨船高”或“供不应求”。
- 进入细分市场二级页的按钮。

点击某个细分市场后，完整复用当前“市场大盘”的分析能力，并按该细分市场过滤，包括趋势、体量、价格带、品牌与 ASIN 垄断、卖家分布、新老品、上架时间、BSR、评分、评论等。这里不是只复制几张摘要图，而是将现有市场大盘完整嵌入当前项目、当前细分市场的二级页。

细分评分必须说明计算依据；样本不足时显示“低可信度”，不能把缺数据误判成低机会。

### 看竞对：回答核心竞争力和“我们如何赢”

竞品样本至少包含头部、跟随者和新进入者，允许每类增加多个样本。首页重点呈现：

- 产品力：功能、规格、材料、质量、设计、价格、变体、用户评价与需求满足程度。
- 运营力：Listing 表达、主图/A+、流量结构、关键词覆盖、评价壁垒、上新节奏和产品矩阵。
- 用户匹配：竞品服务的是谁、使用场景是什么、满足了哪些需求、未满足哪些需求。
- 核心竞争力：为什么用户选择它，哪些能力难以复制。
- 可攻击缝隙：哪条明确需求仍未被满足，我们凭什么赢。

推荐使用“需求维度 × 竞品”的满足矩阵作为首屏核心组件，而不是只并排展示三个 ASIN 的数据列。单 ASIN Listing、图片、A+、流量词、变体矩阵和历史趋势进入三级详情。

### 看自己：账号背景自动带入 + 品类专属 AI 提问

- 通用背景信息在账号设置中维护一次，包括团队能力、供应链、预算、类目经验、渠道、内容能力、利润边界、MOQ、合规与风险偏好。
- 进入项目时自动读取账号背景，不要求用户重复填写长文本。
- AI 根据当前品类、目标需求、细分市场和竞品缝隙生成 3–7 个针对性问题；问题优先使用选择、量化输入和简短回答，避免大段自由填写。
- 输出必须回答：哪些优势能承接机会、哪些能力需要补齐、哪些边界会直接否决机会、相对于竞品我们具体如何赢。
- 用户回答和账号背景有冲突时，以项目内最新回答为准，但不自动覆盖账号通用背景。

### 看机会：只输出经过综合判断的 0–N 个机会

- AI 综合用户需求、细分市场、竞品缺口、自身能力边界生成机会。
- 允许结果为 0；此时必须区分“已判断无机会”和“证据不足暂不能判断”，并列出原因。
- 有机会时按价值排序，但不强制只推荐一个。
- 机会必须同时对应明确需求和成立路径：市场水涨船高/供不应求，或竞品未满足需求；不能只因为市场大或关键词热就判定为机会。
- 机会卡显示机会描述、目标用户、场景/JTBD、机会类型、市场证据、竞品缺口、自身适配、主要风险、AI 评分、证据可信度和人工结论。

### 验收清单

- [ ] 看用户产生的需求分类可以直接成为看市场的细分标准。
- [ ] 每个细分市场都有独立二级页，并完整复用现有市场大盘能力。
- [ ] 看竞对同时输出产品力、运营力、用户需求满足矩阵和“如何赢”。
- [ ] 看自己默认读取账号背景，并生成不超过 7 个品类专属问题。
- [ ] 看机会允许输出 0–N 个结果，且 0 结果有明确、可追溯的原因。

## 4. P0｜建立 AI 机会识别、人工复核、原始证据与推理透明度

### 问题

当前看机会页面能读取机会卡和候选需求，但缺少完整的用户操作：候选需求无法在界面中确认成正式机会，机会内容、评分、结论也缺少清晰的编辑和复核流程。同时，当前评分过度依赖各看完成百分比；完成资料不代表某个机会更好。

### 机会生成与确认流程

`五看数据就绪 → AI 识别 0–N 个候选机会 → 用户查看证据与推理 → 确认/编辑/删除 → 形成正式机会结论`

- 点击“综合判断机会”后，AI 读取当前项目的五看结构化结论，不直接读取无限量原始数据；必要证据以摘要和引用 ID 传入。
- AI 可以生成 0–N 个候选机会。候选默认带“AI 候选”状态，不直接视为最终结论。
- 用户可以确认、编辑、合并、删除或要求 AI 重新分析；确认后的机会进入最终报告。
- 用户允许调整机会内容和最终结论；AI 原始结果保留在版本记录中，便于审核者区分 AI 判断与人工修改。
- 当前 Phase 0 不增加验证任务、负责人、截止日期或项目执行状态。

### 机会评分规则

机会评分建议由以下维度组成，但必须基于该机会自身证据，而不是页面完成度：

| 维度 | 建议权重 | 判断内容 |
| --- | ---: | --- |
| 需求强度 | 25 | 频率、严重度、付费意愿、关键词与 VOC 一致性 |
| 市场机会 | 25 | 体量、趋势、供需、价格带、集中度、新品窗口 |
| 竞品缺口 | 25 | 需求未满足程度、共同缺陷、替代方案代价、壁垒 |
| 自身适配 | 15 | 供应链、能力、预算、经验与风险边界 |
| 证据可信度 | 10 | 样本覆盖、数据源、时效性、矛盾程度 |

总分之外仍要单独展示“证据覆盖度”，避免 80 分但只有单一来源证据的机会看起来过度确定。用户可以调整最终判断；Phase 0 暂不开放复杂权重编辑器，以免增加学习成本，后续可在设置中扩展。

### 机会卡二级页

点击机会卡进入二级页，分为三个固定区域：

- 结论：机会是什么、属于哪一种机会类型、适合谁、为什么现在成立。
- 证据：按看用户、看市场、看竞对、看自己分组展示，每条可点击打开原始关键词、评论、图表、ASIN 或账号回答。
- 推理：展示 AI 从证据到结论的结构化推理链，同时展示反证、风险、缺失信息和人工修改记录。

不建议展示模型的冗长自由文本思考过程；应展示可审核的“证据 → 判断 → 结论”结构化解释。

### Prompt 管理中心新增预设

以下预设必须默认存在、可查看、可编辑、可恢复默认，并记录版本：

| Prompt 名称 | 用途 | 核心输入 | 结构化输出 |
| --- | --- | --- | --- |
| 看自己·品类引导问题 | 根据账号背景和当前品类生成问题 | 账号背景、需求分类、目标细分、竞品缝隙 | 3–7 个问题、问题类型、选项、提问原因、影响维度 |
| 五看·综合机会识别 | 生成 0–N 个候选机会 | 五看结论、证据引用、研究目标、站点 | 机会数组或空数组、无机会/证据不足原因 |
| 机会·反证审查 | 主动寻找不成立的证据 | 单张机会卡及全部引用证据 | 反证、风险、证据冲突、需要降级的结论 |
| 机会·审核摘要 | 生成给同事或老板看的结论 | 已确认机会、人工修改、关键证据 | 最终建议、机会排名、主要依据、保留意见 |

“五看·综合机会识别”的输出至少包含：机会标题、机会类型、目标用户、场景、JTBD、未满足需求、当前替代方案、市场成立依据、竞品缺口、自身适配、风险、分维度评分、证据覆盖度、证据引用 ID、结论置信度，以及无机会时的原因数组。

### 验收清单

- [ ] AI 能根据真实五看数据输出 0–N 个候选机会，而不是强制生成机会。
- [ ] 用户能确认、编辑、合并、删除或重新生成候选机会。
- [ ] 每个评分维度读取该机会的具体证据，不使用五看完成百分比代替业务质量。
- [ ] 每张机会卡都能查看原始证据、结构化推理、反证和人工修改记录。
- [ ] 四个 Prompt 预设出现在 Prompt 管理中心，可编辑、恢复默认并有版本标识。
- [ ] 当前版本不出现验证任务、负责人、截止日期等后续执行能力。

## 5. P0｜围绕“30 分钟得出结论并分享”优化 UI、引导和 HTML 报告

### 30 分钟标准路径

| 时间 | 用户动作 | 系统应提供的帮助 |
| --- | --- | --- |
| 0–2 分钟 | 新建项目，填写研究目标和站点 | 自动建议项目名，提示可导入的数据 |
| 2–8 分钟 | 看用户，导入/抓取关键词与 VOC | AI 自动形成需求分类、画像、JTBD、决策路径 |
| 8–15 分钟 | 看市场，确认需求细分 | 自动计算各细分机会评分，进入目标细分查看完整大盘 |
| 15–22 分钟 | 看竞对 | 自动推荐头部、跟随者、新进入者，输出产品力/运营力和需求缺口 |
| 22–26 分钟 | 看自己 | 自动带入账号背景，回答 3–7 个品类问题 |
| 26–30 分钟 | 看机会并导出 | AI 生成 0–N 个机会，用户复核后导出 HTML |

这是新用户在已有数据源或可抓取数据正常的前提下的目标路径；如果缺少 AI、MCP 或必要数据，应在开始前明确提示，不能让用户做到一半才发现无法完成。

### UI 排版规则

保持现有靛青/紫色、白色卡片、大圆角、柔和阴影和克制渐变，不更换视觉风格，只调整层级：

- 每页只有一个主标题、一句最强结论和一个主操作。
- 删除重复英文 eyebrow 或将其降为面包屑，避免与中文标题重复。
- 同一业务块最多两层容器，减少“大卡套指标卡再套摘要卡”。
- 主结论区占约 8 列，风险/下一步占约 4 列；中等屏幕改为单列。
- 关键正文不低于 14px，说明文字不低于 12px；状态必须同时有文字，不能只用小圆点和颜色。
- 重要需求、证据和风险允许展开，不能用永久截断隐藏关键内容。
- 所有空状态统一回答：为什么为空、缺什么、点击哪里补齐、补齐后会得到什么。
- 各二级页右上角主按钮位置统一，例如“生成需求分类”“计算细分评分”“分析竞品”“生成引导问题”“综合判断机会”。

### HTML 报告需求

HTML 报告是 Phase 0 的正式交付物，不是简单把页面打印出来：

- 文件可独立打开，基础样式和关键图片/图表应内嵌或随包携带，避免分享后资源失效。
- 报告首页必须直接展示研究目标、站点、最终结论、机会数量和生成时间。
- 正文按“用户需求 → 市场细分 → 竞品缺口 → 自身适配 → 机会结论”组织，不按工具菜单顺序堆图。
- 有机会时展示 0–N 张正式机会卡及排名；无机会时明确展示原因和证据不足项。
- 每个结论附关键证据摘要与来源编号；报告末尾提供证据索引和分析口径。
- 区分 AI 原始判断、用户修改和最终确认，便于同事或审核者复核。
- 图表选取以支持结论为原则，不把市场大盘所有图表无差别塞入报告。
- 桌面浏览和打印均需易读；导出前提供目录、报告标题、作者/项目成员和备注编辑。

### 验收清单

- [ ] 有数据和配置的首次用户可在约 30 分钟内得到“0–N 个机会 + 原因”。
- [ ] 任一步缺数据或配置时，系统在开始前说明影响并提供解决入口。
- [ ] 每页只有一个视觉主任务，用户无需猜下一步按钮在哪里。
- [ ] 1024px 宽度下不出现卡片过窄、按钮挤压或关键文字不可见。
- [ ] HTML 报告脱离 App 后仍能正常打开、阅读主要图表和完成审核。
- [ ] 报告内容围绕机会结论组织，并能追溯证据、AI 判断和人工修改。

## Phase 0 建议实施顺序

`需求主线与项目内路由 → 看用户分类 → 细分市场二级页 → 竞品需求满足矩阵 → 账号背景与看自己提问 → AI 机会识别与证据页 → HTML 报告 → 项目中心与全局 UI 收口`

先打通一条真实品类的 30 分钟闭环，再扩展更多项目管理和后续验证能力。Phase 0 暂不投入多项目驾驶舱、任务执行、负责人、截止日期、提醒和实验管理。
