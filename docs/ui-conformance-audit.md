## 三、本轮修了什么（提交见 git log）

1. **看用户 ④ 细分标准**（线框图 Screen 3 第 4 块）：新增 `SegmentStandard` 数据结构（勾选的需求域有序，首个为主标准 + 理由），区块内可勾选/设主标准/写理由/下钻看明细；看市场"方案 A 按需求域切"会优先采用这里的标准。
2. **看市场「查看完整大盘 →」**（Screen 4）：细分评分卡与方案卡内每个细分各有一个入口；点击后打开老版市场大盘整页，并在顶部显示「当前：X（来自看市场）」+「切到全市场（清除筛选）」。
3. **看竞对 L3 下钻入口 ⑦⑧⑨⑩**（Screen 5）：每张竞对卡一行四个入口，ASIN 自动带入；⑩ 走新通路直达评论 VOC / 用户洞察。
4. **看机会「全局先后建议」**（Screen 7）：独立区块，确定性排序（评分 → 覆盖度 → 前置资源缺口）+ 每条的排序理由 + 已拍板标记，并明写"先做哪个由你拍板"。

## 四、仍存在的差异（已知，未修）

**⏳1 决策草稿未"全程常驻"**（线框图 Screen 2 标为"核心 IA 变化"）
现状：决策草稿在「概览」页的向导组件里；切到看用户/看市场等 Tab 后看不到。
建议改法：把草稿抽成 `DecisionDraftRail`，由项目壳（`ProjectWorkspace`）在右侧常驻渲染，向导内不再重复。
代价：需要把 `LookWizardPanel` 的草稿列拆出来，涉及 2 个组件的结构调整。

**⏳2 导出报告未按 §1-§7 固定叙事**
现状：报告包含全部内容，但章节顺序是「Go/No-Go → 四看摘要 → 机会卡」，没有线框图第 8 屏要求的 §1 研究目标 …§7 证据索引，也没有独立的"证据索引"章节。
建议改法：`buildOpportunityReportHtml` / `buildOpportunityMarkdownReport` 改为按 §1-§7 编排，并把 `Evidence` 列表渲染成 §7 证据索引（每条结论 → 来源编号）。

**⏳3 二级页"独立页 vs 内联"的形态差异**
①②③④⑪⑫⑬⑭ 在线框图里是独立 L3 页，实现上是"看内联区块 + 可展开明细"。
判断：内容与下钻都在，差别是**页面形态**（是否开新页面）。若你要求严格按图（每个都有独立页面与返回），需要再拆 8 个页面组件——建议先确认是否真的需要，因为内联下钻的操作步骤更少。

**⏳4 ⑧⑨ 未精确落到 Tab**
"主图逐张对比""流量结构"目前只把 ASIN 带进竞品明细，未自动切到对应 Tab（老版模块内部 Tab 未接外部入参）。
