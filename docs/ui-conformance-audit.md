## 三、本轮修了什么（提交见 git log）

1. **看用户 ④ 细分标准**（线框图 Screen 3 第 4 块）：新增 `SegmentStandard` 数据结构（勾选的需求域有序，首个为主标准 + 理由），区块内可勾选/设主标准/写理由/下钻看明细；看市场"方案 A 按需求域切"会优先采用这里的标准。
2. **看市场「查看完整大盘 →」**（Screen 4）：细分评分卡与方案卡内每个细分各有一个入口；点击后打开老版市场大盘整页，并在顶部显示「当前：X（来自看市场）」+「切到全市场（清除筛选）」。
3. **看竞对 L3 下钻入口 ⑦⑧⑨⑩**（Screen 5）：每张竞对卡一行四个入口，ASIN 自动带入；⑩ 走新通路直达评论 VOC / 用户洞察。
4. **看机会「全局先后建议」**（Screen 7）：独立区块，确定性排序（评分 → 覆盖度 → 前置资源缺口）+ 每条的排序理由 + 已拍板标记，并明写"先做哪个由你拍板"。
5. **决策草稿全程常驻**（Screen 2，原 ⏳1）：抽出 `DecisionDraftRail`，由 `ProjectWorkspace` 在右侧常驻渲染（六个 Tab 都在），向导内重复列删除，保存后 `bumpDraft()` 刷新右栏。
6. **⑧⑨ 精确落到 Tab**（Screen 5，原 ⏳4）：`competitorDrilldown.ts` 单一来源 + `CompetitorHub` 的 `preselectedResultTab`/`resultTabRequestKey`（一次性应用，不抢用户手动切换），⑨ 直达流量视图。
7. **线上白屏修复**：`React #310`（hook 顺序）—— `UserLookView` 的 `useState` 曾落在 `if (!data) return` 之后；已移回 hook 区，并加 `tests/hookOrder.test.ts`（AST 级）守卫。
8. **二级页 ①②③④⑪⑫⑬⑭ 落成独立 L3 页**（原 ⏳3）：新增 `src/utils/l3Pages.ts`（8 页注册表 + 线框图四句契约）、`src/components/L3Sheet.tsx`（全屏页壳：返回/Escape/滚动锁/dialog 语义/契约信息条）；`ProjectWorkspace` 唯一渲染该页壳并把 `onOpenL3` / `onRegisterL3Bodies` 传给「看用户 / 看自己 / 看机会」；
   8 个内联区块抽成带 `variant` 的导出组件（`SearchPathDetailBlock` / `SearchPreferenceDetailBlock` / `NeedTreeDetailBlock` / `SegmentStandardBlock` / `AccountBackgroundBlock` / `CategoryQuizBlock` / `OpportunityEvidenceChain` / `OpportunityRoadmapBlock`），内联与二级页共用同一份实现，**没有复制 markup、没有复制业务逻辑**；`tests/l3Pages.test.ts` 10 条断言守住（含"标记级片段只渲染一次"的反重复守卫）。

## 四、仍存在的差异（已知，未修）

**⏳1 决策草稿未"全程常驻"** → **已修（本轮）**
改法已落地：抽出 `src/components/DecisionDraftRail.tsx`，由项目壳 `ProjectWorkspace` 在右侧 `xl:sticky` 常驻渲染（看用户/看市场/看竞对/看自己/看机会/报告 六个 Tab 都在）；`LookWizardPanel` 内重复的草稿列已删除，改为"草稿在右侧常驻"的提示；向导每次保存后 `bumpDraft()` 通知右栏刷新（`draftNonce`）。
线框图 Screen 2 的"核心 IA 变化"由此对齐：草稿（进度/下一步/未满足需求/缺什么/证据/快照）在任意看都不会消失。

**⏳2 导出报告未按 §1-§7 固定叙事**
现状：报告包含全部内容，但章节顺序是「Go/No-Go → 四看摘要 → 机会卡」，没有线框图第 8 屏要求的 §1 研究目标 …§7 证据索引，也没有独立的"证据索引"章节。
建议改法：`buildOpportunityReportHtml` / `buildOpportunityMarkdownReport` 改为按 §1-§7 编排，并把 `Evidence` 列表渲染成 §7 证据索引（每条结论 → 来源编号）。
本轮状态：**进行中**（HTML/MD 双通道一起改，未完成前不改文档结论）。

**⏳3 二级页"独立页 vs 内联"的形态差异** → **已修（本轮）**

①②③④⑪⑫⑬⑭ 现在是**真正的独立全屏 L3 页**，形态与线框图对齐：

- 唯一注册表 `src/utils/l3Pages.ts`：8 页的 编号 / 圈号 / 归属的看 / 标题，以及线框图每页 `<p class="note">` 原文的四句契约（解决什么问题 / 从哪进入 / 返回去哪 / 依赖哪些数据）。`l3Page()` 对未知编号直接抛错。
- 唯一页壳 `src/components/L3Sheet.tsx`：`fixed inset-0 z-50` 盖在项目之上（右侧决策草稿仍挂在下面，只是被盖住）、粘性页头「← 返回」、`Escape` 关闭、打开期间锁 body 滚动、`role="dialog"` + `aria-modal="true"`、返回按钮 `aria-label="返回"`，页头下方常驻上述四句契约。
- 唯一渲染点：`ProjectWorkspace` 渲染**恰好一个** `L3Sheet`（`const [l3, setL3] = useState<L3Id | null>(null)`，换看时自动关闭）。
- **没有第二份实现**：8 个内联区块各抽成一个导出组件（多一个 `variant?: 'inline' | 'sheet'`），内联与二级页用的是**同一个组件、同一份状态、同一条写回路径**（`scheduleSave` / `persistLib` / `onAnswer` / `persistCards` / `toggleControlPoint`）。
  正文由"拥有这份数据的那一个视图"通过 `onRegisterL3Bodies` 注册给页壳；视图侧用 ref 提供"当前数据能渲染什么"，注册出去的是一层稳定壳（否则父组件每次渲染都收到新函数身份 → `setState` 死循环）。
- 入口按线框图「从哪进入」逐一落位：① 搜索路径图卡右上「查看详情」｜② 搜索偏好卡「查看详情」｜③ 需求区块头 + 每个需求域组的「查看详情」｜④ 细分标准区块「查看详情」｜⑪ 账号背景库「补全背景」｜⑫ 品类选择题「查看本题依据」｜⑬ 每张机会卡「查看详情」｜⑭ 路线图区块「查看详情」。
- 守卫：`tests/l3Pages.test.ts`（注册表顺序、四句契约、未知编号抛错、页壳唯一且行为齐备、8 个入口可逐一 grep、8 个区块组件必须同时出现在内联与二级页、标记级片段只渲染一次、文档口径）。

**⏳3 的残留（形态已对齐，这三处细节仍与线框图有差，未修）**
1. ①「保留层筛选、拖动结果与滚动位置」：实现里没有"层筛选"和"拖动"，页面上是四层流向条；返回主屏后滚动位置由浏览器保留。
2. ⑬「或点卡片标题」：只做了卡片右下「查看详情」，点标题不跳转。
3. ⑭「控制点阈值要能改」：控制点仍只能"点一下即确认"，阈值本身由确定性规则推导，暂不支持在页面上改数值（页面已明写这一点，不假装可编辑）。

**⏳4 ⑧⑨ 未精确落到 Tab** → **已修（本轮）**
新增 `src/utils/competitorDrilldown.ts` 作为单一来源：`DRILLDOWN_ENTRIES`（⑦ 单竞对深度页 → listing ｜ ⑧ 主图逐张对比 → listing ｜ ⑨ 流量结构 → traffic ｜ ⑩ 评论与画像 → 用户洞察）+ `shouldApplyDrilldownTab()`（一次性应用：同一 nonce 只应用一次，用户之后手动切 Tab 不会被抢回）。
