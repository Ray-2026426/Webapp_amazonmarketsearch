   **「拖动结果」故意不实现（不是待办）**：线框图这句的本意是"把词卡拖到别的层即改归属"（`docs/ui-wireframes-l3.html` ① 的「拖动改层」+ 人工修改记录）。本轮**明确不做拖拽**，理由：四层顺序是漏斗的定义，而层与层之间的保留比例是**量出来的确定性数字**（各层搜索量，缺量时退化为词数口径，`computeSearchPathFlow` 算出）；一旦允许人手把词拖到别的层，"漏斗"声称的结论就变成可以由一次手势改写的展示内容，与"AI 只解释、数字必须确定性可追溯"的产品铁律冲突。页面上用一行短文案把这件事说清楚（「顺序与比例都是量出来的，不是偏好设置」「不支持拖动排序」），不假装可以拖。
