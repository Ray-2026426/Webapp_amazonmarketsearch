# Kairo 亚马逊市场机会洞察 App 需求说明

> 版本：V3.0 开发交接版
> 日期：2026-09-18
> 用途：给产品、设计和开发人员快速对齐“为什么做、给谁用、用户怎么用、系统要做什么”。
> 本文是当前产品真相源；旧 PRD 和旧线框图只作交互素材参考。

---

## 1. 一句话说清产品

Kairo 是一个给亚马逊产品经理和 GM 使用的市场机会洞察 App：用户输入关键词、ASIN 或品类名称，系统通过卖家精灵 MCP 取数，通过 AI 按“看用户 → 看市场 → 看竞对 → 看自己 → 看机会”的方法完成分析，最终输出 0–N 张有证据、可复核的机会卡。

它不是“展示更多图表”的数据看板，而是帮助用户回答三个问题：

1. 这个市场是否存在我们可以抓住的未满足需求？
2. 机会具体在哪个细分市场、哪类用户、哪个需求缝隙？
3. 我们相比对手靠什么赢，并且我们是否真有能力抓住？

---

## 2. 核心价值

### 2.1 用户现在的问题

亚马逊市场调研需要在关键词、市场数据、Listing、评论、图片、供应链和利润之间反复切换。传统工具主要提供数据，但不会帮用户把数据组织成“需求 → 细分市场 → 竞对缝隙 → 我方能力 → 机会”的完整推理链。结果通常是数据很多，但仍然不知道要不要进入、从哪里进入。

### 2.2 Kairo 提供的价值

- **替用户完成重复取数和整理**：MCP 拉取关键词、ASIN、Listing、评论和市场数据；也允许上传卖家精灵导出表。
- **把数据转成结构化判断**：AI 负责分类、聚类、总结、解释和候选机会生成。
- **把五看方法论内化到流程**：用户不需要自己设计分析顺序，只需要在关键节点确认、修改或否决。
- **让每个结论都能复核**：机会卡可回溯到需求分类、关键词、评论原文、ASIN 字段和市场数据。
- **允许得出“没机会”**：0 张机会卡是正常结果；系统还要区分“已判断无机会”和“证据不足，暂时无法判断”。

## 3. 目标用户

### 3.1 核心用户

| 角色 | 使用场景 | 最需要的结果 |
| --- | --- | --- |
| 亚马逊产品经理 / 选品人员 | 找新品、定义产品、选细分市场 | 明确的需求分类、市场切法、竞对缝隙和候选产品方案 |
| GM / 项目负责人 | 审核品类是否值得投入 | 看得懂、有理由、能追溯的机会卡和结论 |

### 3.2 次要用户

| 角色 | 使用方式 |
| --- | --- |
| 运营 | 从竞对对比中理解 Listing、流量和用户诉求上的胜负手 |
| 供应链 / 采购 | 回答看自己中的可交付性、成本、MOQ、周期和合规问题 |
| 决策审核者 | 通过导出的 HTML 阅读结论和证据链，不必进入 App 操作 |

## 4. 什么叫“机会”

本产品不把“市场大”或“关键词涨了”直接等同于机会。一个可被识别的机会必须属于以下两大类之一，并经过“我们能否抓住”的检查。

### 4.1 机会 A：水涨船高的市场

市场整体需求迅速增长，供给暂时没有充分跟上，新进入者有较高概率分到增量。

该类机会要回答：

- 增长是短期波动还是持续趋势？
- 新增供给和 ASIN 数的增长是否仍慢于需求增长？
- 是否可以通过产品矩阵扩大规模，并分散单品和市场衰落风险？

V1 只识别这类机会并给出“建议规划产品矩阵”的理由，不在 App 内完成矩阵排期和执行管理。

### 4.2 机会 B：竞对没有满足的需求缝隙

用户需求已经存在，但当前竞品没有充分满足，我方可以从缝隙切入并逐步抢占份额。必须明确属于哪一种赢法：

1. **人无我有**：对手没有提供，我方能提供关键功能、组合、场景或体验。
2. **人有我优**：对手已提供，但我方在产品效果、质量、视觉表达、Listing 说服力或流量承接上明显更好。
3. **人优我廉**：对手产品已经较好，但我方能在保证用户价值和利润底线的前提下，提供更低的总价格或更高性价比。

竞争不只比产品方案，而是比总成本与总差异化：**产品方案 + Listing 打造 + 运营推广 + 供应成本**。任一路径无法成立时，系统应给出“暂无赢面”，不得强行生成机会。

## 5. 版本边界

### 5.1 本期必须完成：五看

- 看用户
- 看市场
- 看竞对
- 看自己
- 看机会
- 数据源接入、证据回溯、人工确认、报告导出

### 5.2 本期明确不做：三定与执行管理

- 不做定目标、定策略、定控制点的完整功能。
- 不做 0–30 天 / 30–90 天路线图、任务、截止时间、提醒、项目进度管理。
- 不让 AI 代替人做最终投资或立项决策。
- 不做泛用 BI，不把所有卖家精灵字段默认堆在主屏。

机会卡可提示“下一步应验证什么”，但这只是为了帮助人理解结论，不等于三定或任务管理。

## 6. 用户如何使用

### 6.1 主流程

1. 新建调研项目，选择站点，输入一类起点数据：1–N 个关键词、1–N 个 ASIN，或 1 个亚马逊品类名称。
2. 系统识别品类、扩展关键词、挑选代表 ASIN，并说明本次将抓取什么。
3. 用户确认后进入看用户，检查并修改 AI 生成的需求分类。
4. 进入看市场，通过 MCP 取数或上传“产品表 + 历史表”，确认市场标签和目标细分市场。
5. 进入看竞对，确认 2–6 个对比 ASIN，查看产品、Listing、运营、价格与评论的横向对比和需求缝隙。
6. 进入看自己，基于已有背景信息回答 3–5 个与本品类直接相关的问题。
7. 进入看机会，阅读 0–N 张机会卡，查看得分、理由、反证和证据，并由用户确认、修改或驳回。
8. 导出一份可分享的 HTML 调研报告。

### 6.2 交互原则

- 每一看都先展示一句结论，再展示证据，最后才展开原始数据。
- AI 负责起草，人负责拍板；人工修改必须保留记录，AI 重跑不得静默覆盖。
- 需求分类是五看的共同索引。修改需求后，已完成的市场、竞对和机会结论必须标记为“需复核”。
- 每一步允许返回修改；不鼓励直接跳步。如必须跳过，应明确说明会影响哪些结论和置信度。
- 对不熟悉统计指标的用户，指标旁必须有人话解释，不允许只给缩写。

## 7. 五看功能需求

## 7.1 看用户：先定义人和需求

### 目标

从关键词和竞品评论中还原这个品类的用户、场景、需求、痛点、偏好与决策路径，形成后续分析共用的“需求地图”。

### 输入

- 1–N 个关键词；或
- 1–N 个 ASIN；或
- 1 个亚马逊品类名称；
- 必选站点，可选调研目的和备注。

### 系统处理

1. 识别输入属于哪个品类，如有歧义，给出候选品类让用户确认。
2. 通过 MCP 扩展关键词列表，保留搜索量、趋势、关联程度和来源。
3. 为该品类选择 3–5 个代表 ASIN，尽量覆盖绝对头部、紧密跟随者、腰部、尾部和新品。如数量不足，系统必须说明缺少哪个角色。
4. 抓取这些 ASIN 的标题和评论。评论样本要同时包含好评、差评、高赞评论和近期评论，不能只看低星。
5. 对关键词和评论进行聚类与交叉验证，识别：人群、使用场景、任务/目的、需求、痛点、偏好、购买决策因素和决策路径。
6. 形成可编辑的需求分类树，支持重命名、合并、拆分、删除和人工新增。

### 主要输出

- 品类一句话定义。
- 核心用户人群与场景。
- 需求分类树，每个需求都有唯一 ID。
- 用户痛点、偏好和购买决策因素排名。
- 从泛词到属性/场景/功能词的搜索决策路径。
- 每个结论对应的关键词和评论原文证据。

### 完成条件

用户确认需求分类树和主要用户特征后，才进入看市场。

## 7.2 看市场：用用户需求重新切市场

### 目标

不只看大盘，而是从消费者决策角度对品类进行标签化和细分，看清每个细分市场的规模、趋势、供需和竞争情况。

### 数据输入的两种方式

1. **MCP 自动取数**：根据上一步识别的品类和 ASIN 范围，获取 ASIN 当月数据和历史销量数据。
2. **手动上传**：用户在卖家精灵“选产品”中，通过“导出”下载产品表，通过“导出明细”下载历史表；两个文件必须被识别并配对。

### 系统处理

1. 检查产品表、历史表的时间范围、字段完整度、重复 ASIN 和异常值，先显示数据质量说明。
2. 对 ASIN 标题进行 N-grams 分析，提取能代表产品核心属性的高频词组。
3. 将“看用户”的需求分类与标题词组合并，形成消费者可理解的细分标签，例如人群、场景、功能、材质、形态、组合和价格带。
4. 系统生成 2–3 套细分方案，说明每套方案的切法、优缺点、未归类率和适用场景，由用户确认或微调。
5. 对全量 ASIN 打标，允许人工修改和复核未归类 ASIN。
6. 为每个细分市场计算规模、趋势、供需缺口、竞争难易和数据可信度，生成细分市场机会分。

### 细分市场默认评分（V1）

| 维度 | 权重 | 判断重点 |
| --- | ---: | --- |
| 市场规模 | 25 | 销量、销售额、单 ASIN 平均产出 |
| 增长趋势 | 25 | 近 12/24 个月增长、稳定性与季节性 |
| 供需缺口 | 20 | 需求增长与新增供给、ASIN 增长的差值 |
| 竞争难易 | 20 | 集中度、头部份额、新品进入、评论壁垒 |
| 数据可信度 | 10 | 覆盖率、时效性、异常值和标签稳定性 |

> 上述权重应配置化，不应写死在前端。AI 只解释分数，不直接修改分数。

### 主要输出

- 已确认的细分标签和全量 ASIN 打标结果。
- 细分市场机会卡排行，展示总分、五个维度、核心数据和一句话判断。
- 点击机会卡进入细分市场大盘二级页，查看趋势、集中度、价格带、品牌、新老品、Top ASIN 和数据质量。
- 由用户选择 1 个目标细分市场传入看竞对。

### 完成条件

用户确认细分方案、完成 ASIN 打标复核并选择目标细分市场。

## 7.3 看竞对：找出需求缝隙和赢法

### 目标

对目标细分市场内不同位置的竞品进行横向对比，找出被反复提及但没有被充分满足的需求，并判断我方可能通过产品、Listing、运营或成本中的哪一组手段取胜。

### 样本选择

- 系统默认推荐 5 个 ASIN：绝对头部、头部紧密跟随者、腰部、尾部、新进入者。
- 用户可替换、增加或删减，最少 2 个，最多 6 个。
- 每个 ASIN 都要显示被选中的理由和角色，用户可覆盖系统角色。

### 系统抓取与对比内容

- 图片：主图和所有附图；A+ 可作 P1，但字段位需预留。
- 商品：标题、五点、规格参数、变体、包装、功能、材质、尺寸、品牌。
- 交易与口碑：价格、优惠、评分、评论数、星级分布、上架时间、BSR、销量和销售额。
- 流量与运营：流量词、自然/广告排名、广告依赖、历史价格、历史排名与销量趋势。
- 用户证据：评论原文、好评点、差评痛点、人群、场景和需求覆盖。

页面将 ASIN 按列并排，将同一字段按行对齐，使差异可直接扫读。图片对比需按“第 1 张对第 1 张”的方式对齐，不能只放一张主图缩略图。

### AI 分析

1. 把每个 ASIN 对需求分类树的满足程度标注为：未满足 / 部分满足 / 已满足 / 证据不足。
2. 总结每个竞品的核心用户、主要爽点、主要痛点和销量来源。
3. 找出多个竞品共同未满足，或某个新进入者正在验证的需求。
4. 从产品方案、Listing 打造、运营推广、总成本四个维度生成可能的竞争方案。
5. 给出“人无我有 / 人有我优 / 人优我廉 / 暂无赢面”的候选判断，并列出支持证据和反证。

### 主要输出

- 2–6 个 ASIN 横向对比表。
- 需求满足矩阵和未满足需求列表。
- 每个缝隙对应的产品、Listing、运营和成本差异。
- 可能的赢法及其理由。

### 完成条件

用户确认至少 2 个竞品、复核关键需求缝隙，并确认候选赢法或“暂无赢面”。

## 7.4 看自己：检查机会是否属于我们

### 目标

不再泛泛地做一份能力问卷，而是针对上一步的具体需求缝隙和赢法，检查我方是否真有产品、供应链、合规、运营和资金能力抓住。

### 输入

- 账号中已维护的背景信息：品牌/店铺、资金、供应链、类目经验、团队与运营能力、合规资质、目标财务和风险偏好。
- 看市场选中的细分市场。
- 看竞对识别的需求缝隙和候选赢法。

### 系统处理

1. 系统先利用背景信息自动回答已知项，不重复问。
2. AI 根据具体品类生成 3–5 个问题，以单选/多选为主，优先包含 1 个自由回答问题。
3. 问题必须与某个机会假设直接相关，并显示“为什么问”。
4. 典型问题覆盖：核心工艺能否交付、目标成本能否达到、MOQ 和交期能否接受、认证/专利风险、内容制作能力、自然与广告流量能力。
5. 识别硬约束、可补足短板和未知项。硬约束不满足时，相关机会不能被标为“可直接进入”。

### 主要输出

- 我方对每个候选机会的适配度。
- 已具备能力、可补足能力、硬约束和未知项。
- 哪个背景信息和哪个回答影响了哪个判断。

### 完成条件

用户完成所有必答问题，对未知项选择“暂不确定”也是有效答案，但会降低证据可信度。

## 7.5 看机会：给出可解释、可否决的机会卡

### 目标

整合前四看，判断市场中是否存在我方可抓住的机会，并用统一机会卡给出类型、得分、理由、反证和证据。

### 机会卡必须包含

- 机会名称：用“目标人群 + 核心需求 + 产品/方案”命名，不用空泛口号。
- 机会类型：水涨船高 / 人无我有 / 人有我优 / 人优我廉。
- 目标细分市场、目标用户、核心需求 ID 和关联竞品。
- 总分与分项得分。
- 为什么是机会：用不超过 3 句人话说清需求、市场、竞对和我方的链条。
- 我方怎么赢：分别说明产品、Listing、运营和总成本中哪些是必要条件。
- 支持证据：关键词、评论原文、市场数据、ASIN 对比和背景回答。
- 反证和风险：哪些证据可能推翻当前判断。
- 证据缺口：下一步应先补哪条证据。
- 当前状态：值得验证 / 继续观察 / 不建议进入 / 证据不足。

### 机会卡默认评分（V1）

| 维度 | 权重 | 来源 |
| --- | ---: | --- |
| 需求强度 | 25 | 关键词 + 评论频次、痛感、决策影响 |
| 市场吸引力 | 25 | 目标细分市场的规模、趋势、供需和竞争 |
| 竞品缝隙 | 20 | 需求未满足程度、多竞品共性、赢法清晰度 |
| 我方可行性 | 20 | 产品、供应链、成本、合规、Listing 和运营能力 |
| 证据可信度 | 10 | 数据覆盖、来源一致性、样本和时效性 |

评分只用于排序和解释，不得替代硬约束。任一必要硬约束不满足时，即使总分较高，也不能标记为“值得验证”以上。

### 0 机会的两种状态

1. **已判断无机会**：数据足够，但需求不强、竞对已满足、市场不吸引或我方无法承接。
2. **证据不足**：缺少关键词、评论、历史销量、竞品字段或我方回答，系统只能告诉用户还需补什么，不生成假机会。

## 8. 数据和 AI 的分工

### 8.1 卖家精灵 MCP

MCP 是数据获取层，负责提供开发时实际可获取的关键词、ASIN、Listing、图片、评论、市场与历史数据。开发不应先假设具体 API 名称和字段一定存在，而应在技术设计阶段完成 MCP 能力清单和字段映射。

每条原始数据要保留：数据源、抓取时间、站点、原始识别符、缓存状态和失败原因。

### 8.2 AI

AI 负责：

- 品类识别与歧义说明。
- 关键词、评论、标题的分类和聚类。
- 用户特征、竞品差异、需求缝隙和候选机会的总结。
- 生成看自己的针对性问题。
- 解释确定性评分为什么高或低。

AI 不负责：

- 编造缺失数据。
- 直接改写确定性分数。
- 把推测写成原始事实。
- 在证据不足时强行生成机会。
- 覆盖人工已确认的修改。

### 8.3 确定性系统

字段清洗、数据质量、评分公式、状态机、权限、缓存、版本、导出和修改记录必须由程序规则控制，不交给 AI 自由发挥。

## 9. 信息架构和页面

### 9.1 顶层导航

- 项目中心
- 市场数据工具（可保留现有大盘，但不应分散五看主流程）
- 利润计算器（可保留为独立工具）
- 设置（背景信息、AI、MCP、导出）

### 9.2 项目内页面

1. 项目概览：输入、数据状态、五看进度、当前结论。
2. 看用户主屏：用户与需求地图。
3. 需求证据二级页：关键词、评论原文和人工编辑。
4. 看市场主屏：细分方案、标签和机会卡排名。
5. 细分市场二级页：完整市场数据和 Top ASIN。
6. 数据上传与质量页：产品表/历史表匹配、字段映射和错误。
7. 看竞对主屏：2–6 个 ASIN 横向对比。
8. 竞品证据二级页：图片、Listing、评论、流量和历史。
9. 看自己主屏：背景摘要、3–5 个问题、硬约束。
10. 背景信息页：账号级信息维护。
11. 看机会主屏：0–N 张机会卡。
12. 机会证据二级页：支持证据、反证、缺口和人工修改。
13. 报告预览与导出页。

### 9.3 项目顶部步骤条

步骤顺序固定显示：看用户 → 看市场 → 看竞对 → 看自己 → 看机会。

每个步骤可显示以下状态：未开始、取数中、AI 分析中、待用户确认、已确认、需复核、失败、已跳过。

## 10. 核心数据对象

| 对象 | 作用 | 关键字段示例 |
| --- | --- | --- |
| Project | 一次市场调研 | 站点、输入类型、输入值、品类、状态、版本 |
| SourceRecord | 一条原始数据 | 来源、抓取时间、原始 ID、原文/数值、站点 |
| Demand | 需求分类树节点 | demandId、父级、名称、人群、场景、证据强度 |
| Evidence | 结论和原始数据的连接 | 类型、sourceId、引用片段、支持/反证、可信度 |
| ASIN | 商品和竞品 | 角色、标题、价格、评分、销量、图片、Listing 字段 |
| Segment | 细分市场 | 标签规则、ASIN 池、指标、分项分、总分 |
| CompetitorGap | 未满足需求缝隙 | demandId、关联 ASIN、满足矩阵、赢法、证据 |
| SelfAssessment | 我方适配检查 | 背景快照、问题、回答、硬约束、适配度 |
| Opportunity | 最终机会卡 | 类型、目标用户、demandId、segmentId、赢法、得分、风险、状态 |
| HumanRevision | 人工修改记录 | 修改前/后、修改人、时间、理由、影响的下游结论 |

## 11. 异常、空状态和降级

- **品类无法识别**：显示 2–5 个候选品类，不允许系统静默猜测。
- **MCP 取数失败**：显示失败的数据类型、影响和可选补数方式；允许单项重试。
- **市场数据不全**：允许继续查看已有内容，但相关分数必须降低可信度并标明缺失字段。
- **竞品少于 2 个**：不启动横向结论，引导用户添加 ASIN。
- **无评论**：可以继续做 Listing 与市场分析，但不得输出确定的痛点强度。
- **AI 输出格式错误**：保留原始数据，重试结构化输出，不向用户展示伪完成结果。
- **0 机会**：展示排除了哪些候选、为什么排除、是无机会还是证据不足。

## 12. 报告导出

导出 HTML 的固定叙事顺序：

1. 本次调研输入、站点和数据口径。
2. 用户和需求地图。
3. 市场细分方法和目标细分市场。
4. 竞对对比、需求缝隙和候选赢法。
5. 我方适配度、硬约束和未知项。
6. 机会卡，首页先给结论。
7. 反证、证据缺口和证据索引。
8. AI 判断与人工修改记录。

报告内的每个关键结论必须可回到对应证据；若导出文件不包含原始数据，则必须包含来源编号和摘要。

## 13. MVP 优先级

### P0：没有就不能形成闭环

- 新建项目：关键词 / ASIN / 品类名称。
- MCP 取数与产品表/历史表上传。
- 五看主流程和顶部状态条。
- 需求分类树及人工编辑。
- 全量 ASIN 打标、细分机会卡和细分详情。
- 2–6 ASIN 横向对比、评论证据和需求满足矩阵。
- 看自己 3–5 题与硬约束。
- 0–N 机会卡、反证、证据链。
- HTML 报告导出。

### P1：明显提高分析深度

- 主图/附图逐张对比。
- 流量词和广告结构深度页。
- 历史价格、BSR 和销量联动。
- 报告版本和人工修改 diff。
- 市场标签批量复核和导出。

### P2：后续增强

- 三定、任务与执行管理。
- 团队协作、评论和审批流。
- 多项目机会组合管理。
- 多租户计费和商业化管理后台。

## 14. 验收标准

### 14.1 业务验收

- 使用任一合法输入类型，用户能跑通五看并到达机会页。
- 看用户产出的需求 ID 在看市场、看竞对和机会卡中可一致追踪。
- 修改已确认的需求后，下游结论自动变为“需复核”，不可继续显示为最新结论。
- 看市场能通过 MCP 或两张上传表成功进入细分计算。
- 看竞对强制 2–6 个 ASIN，并可替换样本。
- 看自己只问 3–5 个与当前机会相关的问题，不重复账号背景中已知信息。
- 看机会可正常输出 0 张机会卡，并能分清“无机会”和“证据不足”。
- 机会卡中每个关键结论至少关联 1 条可打开的证据。
- 输出的机会必须属于四种类型之一，或明确为暂无赢面。
- 导出 HTML 在不登录 App 的情况下也可独立阅读。

### 14.2 体验验收

- 每个主屏只有一个最强结论和一个主操作。
- 数据失败时，页面必须说明“缺什么、影响什么、怎么补”。
- 指标缩写、评分、AI 推测和原始事实有明确区分。
- 完成一步后，用户能一眼看到下一步要做什么。
- 在 1280px 及以上屏幕完成主要工作；窄屏可阅读和复核，但竞品横向表可允许水平滚动。

### 14.3 可靠性验收

- 任意一次 MCP 失败都不会丢失已抓取数据和人工修改。
- 同一项目的数据和结论不会污染其他项目。
- 所有 AI 结论保留模型、时间、输入数据版本和人工修改记录。
- 上传的文件字段不匹配时不直接导入，必须先通过映射确认。

## 16. 本版对旧文档的取舍

### 保留

- 现有的靛蓝/紫色、白色卡片、圆角、友好的视觉语言。
- 项目中心、五看步骤条、结论先行、二级证据页、竞品横向对比、细分市场卡和机会卡等核心结构。
- 证据链、人工确认、可返回修改、0 机会合法等原则。

### 修改

- 看竞对默认从 3 个改为 5 个角色样本，用户可调整为 2–6 个。
- 看自己统一为 3–5 个针对性问题，优先包含 1 个自由回答。
- 机会类型明确为“水涨船高 + 三种竞争缝隙”。
- 从看机会中移除路线图、先做后做、资源排期和控制点，这些属于后续三定。

### 不再采用

- 大量“老版模块不能丢”导致的页面堆叠。
- 把开发记录、环境事故、测试日志和产品需求混在同一份 PRD 中。
- 在主流程中默认展开所有工具页和低频设置。
