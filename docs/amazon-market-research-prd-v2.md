## 1. 执行摘要（TL;DR）

**一句话**：这个 App 已经完成了从"五模块分析工具"到"五看工作台"的方法论演进（phase-0 是及格的 0→1），但它现在是一台"零件齐全、装配松散"的机器——**数据联动靠手动搬运、AI 引擎写了没接、市场细分与看用户脱钩、竞对三列对比只有挑选没有对比、机会卡没有行动路线图**。商用化的改革不是加功能，而是做三件事：

1. **把"五看"从表单页改造成向导式决策流**——用户只做选择题和判断题，AI 负责取数、计算、起草（≤10 分钟出 Go/No-Go 结论）。
2. **把"需求分类"做成贯穿五看的唯一索引**——看用户产出需求与细分逻辑，看市场按它做细分，看竞对按它做满足矩阵，看自己按它做适配，看机会按它出卡。消灭全局缓存暗链。
3. **把"机会卡"升级为"决策包"**——每张机会卡不仅说"有没有机会"，还要输出**先做什么、后做什么、前置资源、控制点、Go/No-Go**。

**现状评分**：main 分支 = 工具集（4/10 的商用基础）；phase-0 = 五看闭环已通（6/10）；本地工作区 = 骨架已通血肉未连（**5/10，不能商用**）。

**已确认的 22 项商业决策**（见 §15.1）：内部团队自用为主顺带产品化；平台统一数据池；≤10 分钟 AI 向导；向导式推进；竞对自动抓取+三列对比；看自己六维度全选；在线决策看板+导出；6 个月打磨完整版；**产品名 Kairo；取数口径分档（词 TOP200 / 评论 60 条快速·200 条深度 / 竞对 3 个）；导出仅 HTML+MD；每一轮交付用户自测；双模式；数据双通道（小数据抓、大数据传）；评论构成与缓存；人优我廉须在红线内；新人=表现最好的代表；示例品类薄枕头；一键向导+每步局部重跑；管理员后台 M5；立即修复 Supabase（M0）。**

**改革后的成功标准**（北极星，§3）：
- 新用户（配好数据池）从建项目到拿到"有没有机会 + 机会路线图" ≤ **10 分钟**；
- 机会结论 **100% 证据可追溯**（每条结论可点回原始关键词/评论/图表/ASIN）；
- 机会卡 100% 含执行路线图（先做/后做/前置资源/控制点）；
- 连续 10 个真实品类回放测试中，**0 次**把"证据不足"误报为"有机会"，**0 次**把"无机会"误报为"证据不足"。

### 2.3 最重要的 12 条断链 / 缺陷（V2 必须全部修复）

1. **五看 AI 引擎整体断链**：`lookAi.runLookAnalysis`（含四个看的结构化 Prompt 与 JSON 回填）零调用，五看全部退化为手填表格，"AI 驱动五看"未兑现。
2. **细分数据全局化、无项目快照**：SegmentScoreCards / CompetitorPickerPanel 读全局 IndexedDB，跨项目数据污染；"看市场"细分卡片的选择/捕获回调是死接口。
3. **机会卡无行动路线图**：缺"先做/后做/前置资源/控制点"；优先级矩阵只分象限不给行动顺序；RiskItem / ValidationAction 的 owner、severity、successCriteria 字段类型齐全但 UI 全部丢弃。
4. **竞对三列对比缺失**：头部/跟随者/新人角色只存在于挑选面板；挑好的 ASIN 不自动进入 CompetitorHub 对比池，用户手动重输。
5. **看用户证据链空心**：VOC/关键词工具结论（tagLib、5W1H、JTBD）只以 count 进入看用户；"捕获证据"只是元数据快照。
6. **评分通胀**：机会分中市场/竞品/自身共 55 分只反映页面完成度，与结论质量无关；看自己填"不具备"与填"已具备"得分相同。
7. **"待验证问题"承诺未兑现**：看市场 openQuestions 声称流向后续视角，实际无消费者。
8. **示例数据下五看空转**：demo 加载时主动清空细分（App.tsx 381-390），自动挑选与细分评分在演示态不可用，新用户第一印象是"功能不可用"。
9. **潜伏 bug**：`competitorWorkspace` 键只读不写；isDemo 正则永假；workspaceIdb 白名单缺该键。
10. **上下文割裂的导航**：五看→工具跳转丢失项目上下文（无面包屑、无参数、工具不认项目）；术语三套并存（竞品分析/竞品对比/看竞对；机会卡/黄金坑位/细分机会分）；ProjectCenter 死接线 props + 站点列表重复条目。
11. **市场准入评分卡被默认关闭**（§2.7.1）：`showMarketScorecard` 默认 `false`。**处置：保留在大盘内原样（含开关），不在看市场主屏强推**，看市场主屏用确定性细分机会分做结论。
12. **导出/交付管线分散**：PDF/Excel/飞书/MD 分散在 6 个组件，统一报告页时最易只留一个（§2.7.3 已建矩阵逐条保留）。

### 2.4 phase-0 文档已确认的 26 条 P0 UI 问题（归纳为 5 类）

1. **项目中心像管理后台**（P0-1）：全局统计噪声；项目卡不显示"研究到哪了、当前结论是什么、下一步点哪里"。
2. **五看被表达为五个平级 Tab**（P0-2）：表达不了业务主线（用户分类→市场细分→竞对缺口→机会）；跳工具断上下文、返回丢状态。
3. **五看内容定义错位**（P0-3）：看用户首页以关键词/评论数量为核心而非需求分类；看市场是泛品类总览而非"需求细分评分列表"；看竞对是并排 ASIN 数据列而非需求×竞品满足矩阵；看自己重复填通用长文本；看机会候选无法确认成正式机会。
4. **AI 透明度不足**（P0-4）：缺"结论/证据/推理"二级页；评分未绑定机会自身证据；Prompt 需可维护有版本。
5. **30 分钟闭环的 UI 细节**（P0-5）：缺数据无提前提示；一页多主标题；卡片套卡片；文字过小；状态只靠颜色；关键内容永久截断；空状态不解释；主按钮位置不统一；HTML 报告不是独立审核交付物；1024px 宽度挤压。

### 2.5 环境与部署阻塞项（P0）

> **根因更正（2026-09，用户核实）**：Supabase 项目**不是被删除，而是被免费额度"闲置自动暂停"**（约 7 天无活动触发）。用户在控制台 **Resume** 后，项目 DNS 立即恢复解析（`fbldvwzoqlewoistybto.supabase.co` → Cloudflare IP）、Auth 服务正常响应、数据与存储对象完好（Supabase 原话："所有数据，包括备份和存储对象，均安全无虞"）。
> **我此前的误判**：看到该域名 `DNS name does not exist`，就断言"项目已删除"。事实上**暂停的项目子域名也会停止解析**，两种解释都成立，而我选了更严重的那种——教训：下"不可逆"结论前必须先排除"可恢复"的可能（如暂停/欠费/迁移）。

| # | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| 1 | **免费 Supabase 项目闲置约 7 天会自动暂停**（**本次故障真因，且会复发**） | 用户控制台截图："'Ray-2026426的项目'已暂停…可在 2027-10-12 前恢复"；暂停期间项目子域名停止解析，全环境登录失败 | 登录、注册、云同步全线失效；**表现极像"项目被删"，极易误判** |
| 2 | **多环境共用同一个硬编码库** | `api/auth/_shared.ts` 曾写死默认 `SUPABASE_URL`/publishable key；未配环境变量时静默回落到该值 | 预览/本地/生产互相污染；项目一旦异常全环境一起崩 |

**M0 修复清单（✅ = 本次已完成并验证）**：

1. ✅ **删除代码里的硬编码默认 Supabase URL/Key**（`api/auth/_shared.ts`）：未配置就明确报"未配置"，从此不再静默连某个固定项目；

4. ✅ **本地开发补 `/api` 中间件**（`server/devApiPlugin.ts` + `vite.config.ts`）：`npm run dev` 下登录/云同步可用；
5. ✅ **新增 `.gitignore`**：仓库是公开的，挡住 `.env.local`、`.vercel*`（含生产 service_role key）等敏感文件；
6. ✅ **前端「设置 → 诊断」面板**（`src/components/SystemDiagnosticsPanel.tsx`，接在设置第 6 个 Tab）：读 `/api/health`，逐项显示配置状态与"**缺什么会坏什么**"，并提供连通性探测与按概率排序的排查建议；
7. ⏳ **本地 `.env.local` 补 `SUPABASE_SERVICE_ROLE_KEY` / `APP_JWT_SECRET`**（用户侧，可选但建议）。

**云端步骤（本次多数不需要）**：项目 Resume 后无需新建、无需重跑迁移、无需改环境变量；原清单保留在 `docs/M0-setup-checklist.md`，仅在"项目真的被删除"时按它执行。

## 3. 商用化定位与北极星

### 3.1 产品定位（V2）

> **亚马逊立项决策系统**：输入一个品类意图（品类名 / 关键词 / 竞品 ASIN），10 分钟内输出一份可复核的决策包——**这个市场有没有机会？机会是什么？先做什么、后做什么？需要什么前置资源？卡哪些控制点？**

第一性原理拆解：

- 用户的真实任务不是"看数据"，是**"拍板"**——买不买库存、开不开模具、投不投广告。数据只是拍板前的证据。
- 用户愿意付费的不是图表，是**"替我完成专业分析师的推理，并且我能看懂、能复核、能拿去说服别人"**。
- 傻瓜式的本质不是"功能少"，是**"把方法论内化"**：五看是专家的工作流，向导把专家流变成选择题流。

### 3.2 目标用户与使用强度

| 角色 | 使用场景 | 核心诉求 |
| --- | --- | --- |
| 老板 / 项目负责人（拍板人） | 每周 1-2 次：这个品类做不做、继续投不投 | 10 分钟拿到结论 + 路线图 + 控制点，可转发给团队 |
| 选品 / 产品经理（研究员） | 每周 2-5 次：初筛品类、深挖细分 | 需求→细分→竞对缝隙的推理链可信、可修改 |
| 运营（执行层） | 拿到立项结论后拆 Listing/广告任务 | 决策包里的先做/后做清单可直接执行 |
| 审核者（外部视角） | 阅读导出的报告 | 证据可点击溯源，能独立判断 |

使用强度：每月 1-2 个深度项目 + 每日若干次快筛。**不要**按"每天处理几十个项目"的管理后台设计。

### 3.3 商业路径（内部自用 → 产品化）

- **Phase A（本 PRD，6 个月）**：内部团队自用打磨。数据由平台统一数据池供给（管理员配置密钥 + 用量记账）；导出 HTML/MD 支持对外交付报告（"先卖报告"的钩子）。
- **Phase B（产品化，另立 PRD）**：多租户订阅。V2 预埋三件事：① 项目/数据严格按 workspace 隔离（修复跨项目污染的同时就是租户隔离）；② 数据池用量计费埋点；③ 团队空间与权限（已有雏形）。

### 3.4 北极星与护栏指标

| 指标 | 目标 |
| --- | --- |
| **北极星：可信决策包产出时间**（建项→拿到含路线图的 Go/No-Go 结论） | 数据就绪下 ≤ 10 分钟（快速模式）/ ≤ 40 分钟（深度模式） |
| 证据可追溯率 | 100%：每条结论可点回原始关键词/评论/图表/ASIN |
| 错误立项防护（对抗测试） | 连续 10 个真实品类回放：0 次"证据不足→有机会"、0 次"无机会→证据不足" |
| 五看闭环完成率（7 天内） | ≥ 70%（V1 是 60%，AI 向导应显著提升） |
| 报告复用率（导出的决策包被转发/复用） | ≥ 50% |

## 4. 改革总纲：十条设计原则

1. **先结论，再证据，后数据**。每页一个主标题 = 一句最强结论；一个主操作。图表是证据，不是首页。
2. **用户只做选择题、判断题、拍板**。取数、聚类、起草、计算由系统完成；人确认或修改。任何需要用户"填长文本"的环节都视为设计失败（备注类除外）。
3. **需求分类是唯一索引**。看用户产出的需求分类 ID 贯穿细分标准、竞对满足矩阵行、机会卡需求字段。改一处，下游标"需复核"（复用并强化 applyLookProgressUpdate 链）。
4. **确定性计算与 AI 分权**。评分、进度、权限、利润计算=确定性公式（有测试）；AI 只做聚类、起草、解释，**永不改分、永不替人决策、永不在缺证据时编造机会**。
5. **0 个机会是合法结论**，并显式区分"已判断无机会"与"证据不足，暂不能判断"。
6. **每一步可回退、可跳过（跳过必须标记风险）**。向导不是监狱，是推荐路径。
7. **缺数据先说，不事后炸**。进入项目时即提示"缺什么、影响什么、怎么补"；演示模式全链路可用（修复 demo 空转）。
8. **决策包可交付**。所有结论可导出为独立、可打印、可转发、证据可溯源的 HTML/MD（不做 PPT，用户确认）。
9. **赢的路径必须落到三种之一**。看竞对与看机会的结论必须指明赢法：**人无我有**（差异化）/ **人有我优**（更优）/ **人优我廉**（更便宜，且必须在毛利红线内）；三种都不成立 → 结论为"无赢面/自身接不住"，不是机会。
10. **极简优先，一切服务"快速找到未满足需求"**。每个看主屏只放：一句人话结论 + 一个主操作 + 证据数量徽章；其余全部进二级页。高级/低频功能**默认收起，不删除**；任何看不懂的东西，要么删掉，要么补一句人话解释——没有解释的指标不显示。

### 5.2 关键结构决策

1. **关键词/VOC/竞品三个老模块降为"明细层"**（市场大盘与利润计算器已按用户要求移到侧栏、原样照搬）：从五看的"查看详细分析"按钮打开，打开后顶部保留面包屑（项目 / 看 X / 明细页）与"带回项目"按钮。明细层产出的结论通过"回填项目证据"按钮写入项目快照（消灭手动搬运）。
2. **向导式推进，非线性可回退**：默认顺序 用户→市场→竞对→自己→机会；完成一步解锁下一步（可跳过，跳过标记"该步未验证"并在机会评分中扣证据可信度分）；随时可点回任一步修改，修改触发下游 stale。
3. **"决策草稿"常驻右侧**：从第二步起，右侧面板实时显示"当前证据下可能的机会方向 + 还缺什么"，让用户全程有"我在往哪走"的感知。窄屏（<1280px）折叠为底部抽屉入口。
4. **双模式**：快速模式（默认，每步 3 个以内选择题，AI 全自动取数，评论 60 条）与深度模式（每步展开全部明细页，专家用户，评论 200 条）。同一数据，两套交互。
5. **触发模型（用户确认）：一键向导 + 每步局部重跑**。建项目后点一次「开始分析」，系统按序自动执行取数→看用户→看市场→看竞对→看自己出题，**每一步停在"请确认"卡**等用户确认/修改后进入下一步；同时每步常驻局部按钮：`重新取数`、`AI 重跑这一步`、`手动改结论`。**不做**"每个板块各自一个 AI 按钮、让用户自己决定跑什么"的形态——那等于把方法论的决策负担丢回用户。

**通用规则（所有二级页强制遵守）**

1. **面包屑 + 返回保留上下文**：`项目中心 / 项目名 / 当前看 / 页面名`；返回主屏时保留筛选条件、滚动位置、展开状态（修复 P0-2 第 ⑤ 条）。

> 每看统一页面结构（继承 phase-0 refactor 计划）：

### 6.1 看用户 V2：搜索路径、搜索偏好、需求分类、细分逻辑

**要回答**：用户是谁？怎么搜？搜的过程中在比什么？哪些需求没被满足？市场该怎么切？

**数据从哪来（数据锚点模型——回答"第一步看用户没有数据源怎么办"）**：

- 建项目时用户必须给一个**锚点**（品类名 / 关键词 / 竞品 ASIN 三选一）——这是用户自己的业务意图。**看用户的数据由锚点反查扩展而来，不依赖看市场先完成**：看市场需要的大盘数据晚于看用户取得，没有循环依赖。
- 快速模式固定口径（用户确认）：**词 TOP200 · 评论 60 条 · 竞对 3 个**；深度模式：**评论 200 条**（分档 + 缓存，见下）。
- **评论取样分档（用户确认，因卖家精灵 `review` 每次最多返回 20 条）**：
  - 快速模式 60 条 = 锚点 ASIN 20 条 + 品类头部 2 个 ASIN 各 20 条 = **3 次调用**；
  - 深度模式 200 条 = 锚点 ASIN 80 条（4 次）+ 头部 2 个 ASIN 各 60 条（各 3 次）= **10 次调用**；
  - **缓存 14-30 天**：同一 ASIN 的评论样本在 TTL 内复用，重复分析同一品类不再扣次数；
  - 一律标注来源构成与"基于样本，不代表总体"。
- **双通道取数（用户确认的混合模式：小数据抓、大数据传）**：
  - 🕸 MCP 抓取通道（小数据量）：词 TOP200（关键词扩展/ABA）、评论（快速 60 / 深度 200 条）、竞对 Listing 全字段（§6.3）、竞品标题 TOP30；
  - 📤 上传通道（大数据量）：**产品表 + 历史表（大盘快照）沿用现有 Excel/CSV 上传**——数据量大时 MCP 抓取慢且烧调用次数，默认走上传；可选 MCP 抓取但明示成本与耗时。
- 取数链路（数据池就绪时全自动）：
  1. 锚点=关键词 → 卖家精灵关键词扩展 / ABA → **TOP200 词**（含搜索量、意图分层）；
  2. 锚点=ASIN → 该 ASIN 流量词反查 + 评论；
  3. 锚点=品类名 → 类目 TOP ASIN 榜 → 头部 ASIN 的评论与标题；
  4. **评论样本**（用户已确认口径）：快速模式 60 条（锚点 20 + 头部 2×20，3 次调用）；深度模式 200 条（锚点 80 + 头部 2×60，10 次调用）；缓存 14-30 天复用；
  5. **竞品标题样本**：品类 TOP30 ASIN 标题（供 6.2 细分合成聚类用）。
- **无数据池 / 无 Key 时**（三条补数途径，建项目那一刻就检查并提示，绝不允许做到一半才发现）：
  ① 上传词表 Excel + 评论 Excel；② 粘贴 1-3 个竞品 ASIN，由系统经数据池抓取；③ 全部缺失 → 用内置示例品类（真实品类：薄枕头，用户确认）跑通全流程（醒目标注"示例数据，非真实结论"）。

**输入（系统自动取，用户可补充）**：
- 关键词集（ABA/流量词，快速模式 TOP200）
- 评论样本（快速 60 条 / 深度 200 条，标注来源构成与"基于样本"）
- 竞品标题样本（品类 TOP30，供市场细分参考，实际聚类在 6.2 执行）

**向导步骤（3 个选择题 + 1 次确认）**：

1. **搜索路径图（AI 自动生成 → 用户选择题确认）｜二级页①：搜索路径详情**
   产出：认知词 → 考虑词 → 决策词 → 场景/复购词 的四层漏斗，每层 Top 词、占比、流向。
   选择题示例："AI 判断您的品类中'枕头'层用户先搜大词、再按'睡姿'分化——对吗？A. 对 B. 先按'材质'分化 C. 我来改"。用户可拖动词到别的层。
   主屏只放漏斗图与最强结论，完整词表/占比/流向进**二级页①**（见 §5.5），可"回填项目"。
2. **搜索偏好画像（AI 起草 → 确认）｜二级页②：搜索偏好详情**
   产出：价格敏感度（低价词占比）、功能/材质/品牌词倾向、长尾 vs 大词结构、购买决策焦点（对比什么维度）。
   每条偏好必须挂证据（词 + 评论），点开进**二级页②**。
3. **需求分类树（核心产物）｜二级页③：需求分类树详情（证据链重点）**
   AI 对关键词意图 + 评论 VOC 打标聚类 → 需求分类树（2-3 层，每节点挂证据：关键词证据 ≥2 条 + 评论原文引用 ≥1 条）。
   用户操作：合并 / 拆分 / 重命名 / 排除 / 确认。**确认后的分类获得稳定 ID，成为全项目索引。**
   每条需求标注：已满足 / 部分满足 / 未满足（初判，供看竞对验证）。
   **证据链在二级页③展开**：选中任一需求 → 右侧面板显示关键词证据列表、评论原文引用、覆盖 ASIN、证据强度；证据可点回原始来源。
4. **细分标准建议（联动看市场）｜二级页④：细分标准设置**
   用户把某层需求分类标记为"**作为市场细分标准**"（可多选，可组合"需求×场景×价格带"）。
   示例：按"睡姿（侧睡/仰睡/俯睡）"切 → 看市场将按此维度聚合商品并评分。
   **二级页④** 实时预览：将切出几个细分、各含多少 ASIN，确认后写入看市场。

**产出物**：搜索路径图、搜索偏好卡、需求分类树（带证据）、细分标准建议；四者均可下钻到各自二级页（① ② ③ ④）。完成条件：≥1 条"未满足/部分满足"需求且每条挂证据。

### 6.2 看市场 V2：需求驱动的市场细分（核心改革）

**要回答**：哪块细分市场有价值和进入窗口？

**细分合成逻辑（三方合成，替换现在的"手动 ASIN 分组"）**：

```
需求维度（看用户的需求分类）
   × 商品维度（大盘数据的价格带/材质/场景属性）
   × 供给维度（竞品标题关键词聚类：市场在卖什么、怎么自称）
        │
        ▼
  AI 提出细分方案草案（2-8 个细分，每个给：定义、代表 ASIN、为什么这么切）
        │
        ▼
  用户选择题确认/调整（这是傻瓜式的关键：用户改的是"方案选项"，不是原始数据）
        │
        ▼
  每个细分跑确定性评分（复用 segmentScore：趋势0.35/体量0.35/竞争0.3，有测试锁定）
```

**数据通道（用户确认）**：细分聚合所需的产品表+历史表默认来自**上传 Excel**（量大走上传，不烧 MCP 次数）；词/评论/竞品 Listing 走 MCP 抓取。

> **实现说明（M2③ 落地时的刻意偏差，2026-09）**：本节的"AI 提出细分方案草案"落地为 **三个方案全部由确定性规则生成**（A 需求域 / B 价格段×商品属性 / C 竞品标题聚类），AI 的角色是**解释方案差异与盲区**（`segmentAdvice`），prompt 里明确写入"分数与归属不可修改、不得替用户选方案"。
> 理由：① 用户诉求是"细分逻辑要跟上一步（看用户）挂钩"，这靠**命中规则**保证，不靠模型自由发挥；② 与 §4 原则 4 / §8「AI 只解释、不改分」一致——若方案由 AI 生成，评分与归属就无法复现，三例真实品类回放也无法比对偏差；③ 规则全部有测试锁定（单归属、不重叠、收入占比 ≤100%、未归属显式计数）。
> 用户看到的仍然是"2-3 个方案 + 选择题 + 一句利弊"，体验与 PRD 一致；差别只在方案的**来源**。

**向导步骤**：

1. AI 读入看用户的细分标准建议 + 竞品标题聚类结果，输出 2-3 个"细分方案"供选择（例如"按睡姿切 3 块"vs"按材质切 4 块"vs"按价格带切 3 块"），每个方案附一句利弊。
2. 用户选一个方案（可微调：合并/拆分细分），系统按 ASIN 归属聚合商品，对每个细分跑评分 → **细分机会池排行**（卡片：机会分 + 趋势/体量/竞争三分 + 规模 + 均价 + 代表 ASIN）。
3. 点进任一细分 → **二级页⑤「细分市场完整大盘」**：**就是老版"市场大盘"整页，但已自动筛选到该细分**——KPI 卡、趋势、集中度、价格带、价格-评分散点、品牌榜、BSR 分布、上架时间、新老品、评分分布、季节热力、卖家类型/位置、Top 商品表、数据质量提示全部保留（老版图表组件原样复用，§5.6 原则 1）；顶部固定在筛选条：`当前：侧睡枕细分（23 ASIN）` + 切换细分下拉 + "切到全市场"（进侧栏⑲全市场大盘）+ 返回看市场。无 ASIN 映射时显式标"全市场回退"，沿用 phase-0 控制点。
4. **选择目标细分**（单选为主，允许"暂不定，先看全市场"）→ 该细分的 ASIN 自动成为看竞对的样本池。

**产出物**：细分方案确认记录、细分机会池排行、目标细分选择（+ 其 ASIN 列表 → 看竞对）。完成条件：目标细分已选 或 显式选择"暂不定"。

**修复项**：断链 #2（细分按项目快照隔离，选择回调真正生效）、#7（openQuestions 改为结构化"对看竞对/看自己的待验证问题"，被下游消费并在对应页面顶部显示）。

### 6.4 看自己 V2：背景库 + 品类选择题

**要回答**：我们接不接得住？哪些边界会直接否决这个机会？

**两层设计（修复"42 题太重"与"适配度=完成度"两个缺陷）**：

1. **账号背景库（一次性，渐进完善，六维度全量保留）**：
   - 资金与预算（启动资金/广告预算/可承受亏损周期）
   - 供应链（工厂资源/MOQ/账期/交付周期）
   - 类目经验与团队（类目经验/运营/设计能力）
   - 合规资质（认证/商标/专利/品类准入）
   - 目标财务（目标售价/毛利率/净利率红线/回本周期）
   - 风险偏好（验证期长度/库存风险承受）
   
   每项四态（已具备/部分具备/不具备/待确认）+ 备注。**不再强迫一次填完**：进入项目时提示"背景库完整度 40%，将影响适配度可信度"，可随时补。
   
2. **项目内品类选择题（AI 动态生成 5-8 题）**：输入 = 背景库 + 需求分类 + 目标细分 + 竞对缝隙 → 生成与本项目直接相关的选择题（每题 2-5 个选项 + 选项旁"为什么不"说明）。示例："头部竞品已持有'凉感面料'专利。您的供应链能否在 60 天内交付同等级凉感面料？A. 能 B. 能但要 90 天 C. 不能 D. 不确定"。

**适配度计算（V2 修正，确定性公式）**：
- 仅取与目标细分/机会相关的问题子集（相关性由 AI 在出题时标注，用户可改）；
- 每题映射：已具备=1 / 部分具备=0.5 / 不具备=0 / 待确认=不纳入（降证据可信度）；
- **硬约束否决规则**：任何"决策边界"类问题答"不具备/不满足"（如毛利红线达不到、MOQ 超标、认证缺失）→ 关联机会不能推荐"直接进入"，最高"验证后进入"，并在机会卡顶部红条警示。
- 适配度 = 相关题得分均值 × 背景库完整度修正；**完成度与适配度彻底分离**。

**产出物**：背景库、品类问题与答案、优势/缺口/硬约束汇总、每张机会卡的适配度。完成条件：全部动态题已答（或显式"跳过并标记风险"）。

**二级页**：⑪账号背景库（六维度四态 + 完整度进度）、⑫品类选择题与依据（AI 为什么问这题、选项含义、答完对适配度与硬约束的影响）。

```
│ 风险              ：[需求] 侧睡人群占比存疑（中，缓解：测评验证）│

└────────────────────────────────────────────────────────────┘
```

- **先做/后做**：AI 按"验证成本最低、信息增益最高"生成两段时间线（0-30 天 / 30-90 天），每条动作可编辑、可拖序。
- **前置资源**：AI 从四看证据推导资源清单（资金/供应链/认证/素材/团队/数据），并标注"已知缺口"（对照看自己的背景库，缺的资源标红）。
- **控制点**：三类——**准入控制点**（满足才继续，如 CVR、认证通过）、**过程控制点**（监控指标，如退货率、评分）、**止损控制点**（触发即撤，如 ACOS、累计亏损额）。每条含数值与判定，默认由 AI 从利润假设+风险推导，用户必须确认（确认是拍板动作）。
- RiskItem / ValidationAction 的 category/severity/owner/successCriteria/dueDate 全部启用真实 UI（修复断链 #3）。

**优先级与决策摘要**：
- 机会卡按评分排序 + 2×2 矩阵（分数×覆盖度）；
- **全局"先做哪个机会"建议**：AI 给出排序理由（如"O1 与 O2 共用供应链，先 O1 可摊薄 O2 成本"），用户拍板；
- Go/No-Go 汇总：结论（进入 / 验证后进入 / 暂缓 / 放弃 / 无机会 / 证据不足）+ 一句话理由 + 引用证据编号。

**产出物**：0-N 张机会卡（含决策包）、优先级矩阵、全局先后建议、Go/No-Go 结论。完成条件：≥1 张卡已决策 或 零机会结论已人工确认（沿用 phase-0 控制点）。

**二级页**：⑬机会卡详情（证据/推理/反证 三栏 + 人工修改记录）、⑭执行路线图与控制点详情（0-30/30-90 天时间轴、前置资源缺口、准入/过程/止损三类控制点可编辑）。

### 7.2 项目级数据快照（修复跨项目污染）

- 每个项目拥有自己的快照：`marketSnapshot`（商品+历史）、`segments`、`competitorPool`、`reviewSample`、`keywordSet`、`titleCorpus`。工具层/明细页写入"当前项目"快照，而不是全局 IndexedDB 键。

## 8. 评分与决策规则 V2

### 8.1 机会卡评分（权重沿用实现版 25/25/25/15/10，输入全部换血）

| 维度 | 权重 | V2 数据源（修复通胀） |
| --- | --- | --- |
| 需求强度 | 25 | 需求卡的证据强度：频度/严重度/关键词×VOC 一致性/替代代价（确定性折算） |
| 市场机会 | 25 | 目标细分机会分（趋势/体量/竞争）折算；未选目标细分则取全市场分×0.6 |
| 竞品缺口 | 25 | 需求满足矩阵 + 痛点未满足矩阵的"未满足/部分满足"占比 + 缝隙证据数折算 |
| 自身适配 | 15 | §6.4 适配度公式（答案质量×背景完整度），**与完成度无关** |
| 证据可信度 | 10 | Evidence 覆盖：样本量/来源/时效/跨源一致；缺项从分母移除并降覆盖度 |

硬规则：① AI 只解释不改分；② 数据覆盖度独立展示不纳入 100 分；③ 违反硬约束 → 不能推荐"直接进入"；④ 高分≠立项，风险与控制点必须同屏。

### 8.2 细分机会分（看市场，保持不变，已测试锁定）

趋势 0.35 + 体量 0.35 + 竞争 0.3（segmentScore，tests/lookOptimize.test.ts）。

### 8.3 进度与状态机（沿用并微调）

- 五看状态：未开始/进行中/已完成/需复核；完成度由必要证据项计算，禁止拖动，AI 不判断。
- 向导模式新增"已跳过（含风险）"子状态：跳过的看在机会卡证据可信度中降权并在报告标注。

## 10. "傻瓜式"体验细则（10 分钟路径）

### 10.1 计时路径（数据池就绪的常态）

| 分钟 | 步骤 | 用户动作 |
| --- | --- | --- |
| 0-1 | 建项目 | 输入品类名/关键词/ASIN（三选一），回车即开始 |
| 1-4 | 看用户 | 系统按锚点自动取数（词 TOP200 / 评论 60 条 / 竞品标题 TOP30）→ 3 个选择题（确认搜索路径/偏好/需求分类）+ 标记细分标准 |
| 4-6 | 看市场 | 选一个细分方案（2-3 选 1）→ 看评分排行 → 点"选目标细分" |
| 6-8 | 看竞对 | 系统自动抓 3 个竞对（头/跟/新各 1）→ 扫读全量 Listing 三列对比 + 每竞对三块分析 → 确认赢的路径（人无我有/人有我优/人优我廉） |
| 8-9 | 看自己 | 答 5-8 道品类选择题 |
| 9-10 | 看机会 | AI 出候选 → 确认/修改 → 拍板决策 → 导出决策包 |

**关键设计**：每步的 AI 结论都以"请确认"卡呈现（默认接受=点一下"确认"）；全程右侧"决策草稿"显示进展与缺口；任何一步缺数据立即提示"缺 X，影响 Y，[用样例继续] [补数据]"；快速模式固定口径=**词 TOP200 / 评论 60 条 / 竞对 3 个**（深度模式评论 200 条，缓存 14-30 天）；**触发模型=一键向导 + 每步局部重跑**；**每一轮交付由用户本人测试验收，PM 以用户的实测反馈作为下一轮输入。**

### 10.2 防呆与空状态规范（继承 P0-5 并强化）

- 每页一个主标题（结论）、一个主操作；正文 ≥14px，说明 ≥12px；状态=图标+文字+颜色三重表达；关键内容不永久截断（可展开）；
- 空状态四要素：为什么空 / 缺什么 / 点哪补 / 补完得到什么；
- 向导每步完成自动 toast"下一步：看市场（约 2 分钟）"；
- 错误提示带"重试/换源/跳过并标记"三选一；

**M2② 关键设计（确定性优先，AI 只解释不改分）**：

| 规则 | 实现 |
| --- | --- |
| 证据强度不用 AI 主观档位 | `computeNeedEvidenceStrength`：关键词 每条 +12（上限 36）、评论原文 每条 +18（上限 54）、覆盖 ASIN 每个 +5（上限 20）、三类齐全再 +10「跨来源一致」；≥70 高 / ≥40 中 / 其余低 |

**M2① 搜索路径「流向」补充（本轮）**：`computeSearchPathFlow` 把四层按固定顺序对齐，算出每层相对上一层的**保留比例与流失比例**：两层都有搜索量时用搜索量口径（真实需求收缩），否则退化到词数口径并明确标注口径（绝不混算）；搜索量为 0/缺失时返回 `null` 并给出人话说明，不编造比例。AI 提示词同时明确"你不需要也不要输出任何流向百分比"——流向永远由系统算。

**本轮修掉的一个真实 bug（我自己引入的）**：向导在无数据时保存了**空快照**并被当成有效范围，导致 AI 永久跳过取数。已修为「空快照忽略并重新采集」，并在向导"缺数据"卡上给了可点按钮（去取数 / 加载示例）。用户此前反馈的"四步都被跳过"即由此而来。

**同时修掉"看起来正常、其实是没配置"**：旧逻辑用 `/尚未|请先/` 正则把一切都算「已跳过」，导致**没配 AI 模型 Key 时也显示"四步都被跳过"**（用户会以为流程正常）。新增 `src/utils/lookAiFailure.ts`：失败收敛为 `no-key / no-data / parse / other` 四类，**只有 `no-data` 才叫「跳过」**；缺 Key 时向导显示红色结论「四步都没跑：还没有配置 AI 模型 Key（这不是"跳过"）」并给一个直达「设置 → API 与模型」的按钮（`LookWizardPanel` → `ProjectWorkspace` → `App` 透传 `onOpenSettings`）。

**M2③ 细分三方合成（用户核心诉求："细分逻辑没跟上一步挂钩"）**：

| 方案 | 切法（全部确定性） | 什么时候选它 |
| --- | --- | --- |
| A 需求域 | 细分名 = 看用户的需求域；商品按"标题命中该需求的词"**单归属**；每个细分挂上命中的未满足需求 + 证据分 | 结论要能直接回到用户需求与 VOC 证据 |
| B 价格段 × 商品属性 | 价格按分位切三段，段内按样本里最普遍的商品属性（固定词表）对半分 | 要定价、算利润、定卖点 |
| C 竞品标题聚类 | 标题词频（document frequency）取前 4 个词簇，单归属，命中词表给中文释义 | 找"竞对反复强调却仍被差评"的点 |

- 三个方案都是**真切分**：商品不重叠、收入占比合计 ≤ 100%、未归属商品显式计数（不藏长尾）；
- 评分复用 `segmentScore`（趋势 × 体量 × 竞争 → 机会分）；**AI 只能解释差异，不能改分、不能替用户选方案**（prompt 里明写）；
- 推荐公式（确定性）：需求挂钩度 50% + 覆盖率 30% + 收入加权机会分 20%，平局优先需求域方案，且必须声明"最终方案由你选"；
- 选定结果写回看市场（`segmentSchemeId` / `chosenSegmentIds`），看竞对的样本池据此挑选（M2④）。

**M2⑤ 断链 #7 的真实闭环**（不只是显示）：看市场的待验证问题 → 看用户/看竞对页顶**可就地回答**（回答存在下游那一看自己身上）→ 下游 AI 提示词里被强制"必须正面回应，不要编造数据"。

## 16. 简洁性裁剪（本轮审查：消灭"看不懂、用不上"，一切服务快速找到未满足需求）

**总原则（§4 原则 10）**：每个看主屏只放「一句人话结论 + 一个主操作 + 证据数量徽章」，其余全部进二级页；高级/低频功能**默认收起，不删除**；看不懂的东西要么删、要么补一句人话解释。

**主屏最小模板（五个看都遵守）**：

```
┌─ 看市场 ──────────────────────────────────────────────┐
│ 结论（人话，≤20 字）：侧睡细分值得做，先验证"可调高度"。│
│ [AI 起草 · 请确认]     证据 12 条                     │
│ [主操作：确认 → 看竞对]  [次要：重新分析]              │
│ ▾ 查看详情（细分评分 / 完整大盘 / 证据链 → 进二级页）   │
└───────────────────────────────────────────────────────┘
```

**裁剪清单（默认收起 / 简化，不删除）**：

| 项 | 处置 | 理由 |
| --- | --- | --- |
| 利润计算器 | 移到首页侧栏（项目中心下），原样照搬 | 独立工具，不进五看流程，减少项目内噪音 |
| 机会扫描器 | 取消独立页，保留在大盘全市场页内 | 本质是大盘的一个图表，独立成页是过度设计 |
| 市场大盘（全市场） | 照搬原样，不改 | 用户熟悉 |
| 登录页 | 照搬原样，不改 | 无需改 |
| 市场准入评分卡（8 维度） | 保留在大盘内（原样，默认收起），不在看市场主屏强推 | 复杂且默认关闭；主屏用确定性细分机会分即可 |
| 锚点批注 | 默认收起（悬浮小按钮），不常驻显示 | 力量功能，常驻增加视觉噪音 |
| PageQuickNav 18 段导航 | 仅在大盘超长页出现 | 只在需要时出现 |
| 完成度% / 进度环 | 降为次要信息（灰色小字），不作主视觉 | 完成度 ≠ 决策质量 |
| 术语 | 只保留一套（§5.4） | 消除"竞品分析/对比/看竞对"混用 |
| AI 产出 | 每条必须带一句人话解释 + 证据可追溯 | 没有解释的指标不显示 |

## 17. 国内底座迁移（后置，另行立项）

> 用户已确认（§15.1-23）：现阶段沿用 Vercel + Supabase，先把 App 功能做好；国内迁移（免 VPN）在功能打磨完成后另行立项。

**为什么后置是合理的**：当前是"内部团队自用为主"，海外访问可用 VPN 扛；而国内迁移的 ICP 备案（首次约 1-2 周）、数据库改造、认证改造都是重活，现在做会拖慢产品本身。

**迁移目标（届时再细化）**：

| 层 | 现在 | 国内候选 | 说明 |
| --- | --- | --- | --- |
| 数据库 | Supabase Postgres | 腾讯云 CloudBase 云数据库 / 阿里云 RDS | projects/members 表迁移 |
| 认证 | Supabase Auth（已自建 JWT+pbkdf2） | 自建（查 app_users 表）或 CloudBase 认证 | 代码已有自建认证雏形，迁移成本低 |
| 存储 | Supabase Storage | 七牛 Kodo / 腾讯云 COS / CloudBase 存储 | 报告资产、竞品图包 |
| 托管 | Vercel | CloudBase 静态托管+云函数 / 国内 ECS | 前端 + api/* |

**迁移前置门槛**：域名 + ICP 备案（企业/个体户主体），首次约 1-2 周——这是国内免 VPN 的第一道闸，比选哪家云更优先。

**迁移友好护栏（现在就要遵守，避免将来被绑死）**：
1. **数据层已抽象在 `api/*` 服务端函数 + 数据池网关之后**，前端不直接接触 Supabase（现状已如此，§2.6/§11.2）——迁移时只改服务端，前端零改动；
2. 新增代码**不要**在组件层直接 import Supabase 客户端，一律走 api/* 或数据层封装；
3. 认证 token 逻辑（自建 JWT + pbkdf2）保持独立，不依赖 Supabase Auth 的专属特性。

**已知风险（后置期间接受）**：Vercel/Supabase 国内访问不稳定、Supabase 免费额度有限——内部自用阶段用 VPN/海外节点容忍；对外产品化（Phase B）前必须完成国内迁移。
