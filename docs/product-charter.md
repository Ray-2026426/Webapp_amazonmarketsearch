# AmzDev Tool 产品总纲

> 本文是本项目业务目标、产品边界、信息架构与 UI 原则的长期事实源，主要供产品、设计、开发和后续接手的 AI 阅读。
>
> 阅读规则：本文描述“为什么做、最终应是什么”；[Phase 0 业务与 UI 优化 PRD](./phase0-business-ui-optimization-checklist.md)描述“下一阶段具体怎么改”；代码描述“目前实际实现到哪里”。三者不一致时，不要擅自把现状当目标，也不要把目标误认为已经实现。

## 1. 一句话定义

AmzDev Tool 是一个面向亚马逊新品立项与品类研究的机会洞察工作台：把关键词、评论、市场大盘、竞品与团队能力串成一条可追溯的证据链，帮助用户判断一个品类是否存在尚未被满足的需求。

它不是普通数据看板，也不是把多个报告生成器放到一起。产品价值不在“展示更多数据”，而在更快、更可信地回答：

- 这个品类有没有机会？
- 如果有，具体是什么机会？
- 机会为什么成立，证据在哪里？
- 如果没有，是已验证无机会，还是证据暂时不足？

## 2. 用户、场景与成功标准

### 核心用户

- 产品经理：需要把用户需求转成新品定义和立项依据。
- 选品人员：需要快速筛查品类并判断值得深入的细分机会。
- 老板或审核者：需要快速看懂结论、证据、风险和人工判断。

### 核心场景

- 新品立项与新品开发。
- 寻找新的品类或细分市场。
- 对现有目标品类进行阶段性市场监控和复核。

### 使用强度

典型用户每月研究 1–2 个项目，偏深度研究。Phase 0 不应按“每天处理几十个项目”的管理后台设计。

### Phase 0 成功标准

在数据源和 AI 配置可用的前提下，新用户能够在约 30 分钟内：

1. 建立研究项目。
2. 完成用户需求分类。
3. 比较需求细分市场。
4. 判断代表竞品如何满足需求以及还缺什么。
5. 结合自身能力边界完成机会判断。
6. 得到 0–N 个有证据的机会结论。
7. 导出图文并茂、可发给同事或审核者的 HTML 报告。

## 3. 机会的严格定义

产品只承认两类机会：

### 市场型机会

市场水涨船高、需求增长或供不应求，使新的供给仍有进入空间。典型证据包括真实增长、供给不足、新品持续获得销量、合理价格带仍有空档，以及竞争集中度尚未形成不可突破的壁垒。

### 缺口型机会

现有竞品没有完全满足一类明确用户的需求。缺口可能来自功能、价格、质量、使用体验、适用场景、服务、组合方式或其他因素。它必须同时回答“谁的什么需求未满足”“现有替代方案是什么”“为什么现有竞品没解决”。

### 不应直接判为机会的情况

- 市场规模大，但没有增长、供需或竞品缺口证据。
- 搜索量高，但需求已被成熟竞品充分满足。
- 评论里存在零散抱怨，但频率、严重度或付费意愿不足。
- 用户喜欢某个创意，但团队能力、成本、合规或利润边界无法承接。
- 数据不足，却由 AI 为了完成任务强行生成一个机会。

### 输出规则

- 允许输出 0–N 个机会，不设置最低数量。
- “0 个机会”是合法且有价值的结论，但必须解释原因。
- 必须区分“已判断无机会”和“证据不足，暂不能判断”。
- AI 先产生候选机会；经用户确认或修改后，才成为正式机会结论。

## 4. 核心方法：五看，但用户需求贯穿始终

推荐路径是：

`看用户 → 看市场 → 看竞对 → 看自己 → 看机会`

项目五看界面统一使用“看竞对”，因为分析对象不仅是单个商品，还包括品牌、卖家、产品组合和运营能力。独立历史工具仍可使用“竞品分析”作为工具名；新代码不得把“五看视角”和“单品工具”混为同一层级。

这不是五个孤立报告。“看用户”形成的需求分类是后续所有分析的索引：

- 看市场：按需求分类划分细分市场并评分。
- 看竞对：判断代表竞品满足了哪些需求、没有满足哪些需求。
- 看自己：判断团队是否有能力承接这条需求与竞品缝隙。
- 看机会：综合四看证据，形成 0–N 个正式结论。

### 各看的业务契约

| 视角 | 必须回答的问题 | 核心产物 |
| --- | --- | --- |
| 看用户 | 谁在什么场景完成什么任务，什么需求仍未被满足？ | 需求分类、用户画像、场景、JTBD、决策路径、替代方案、需求证据 |
| 看市场 | 这类需求对应的细分市场有没有价值和进入窗口？ | 细分市场机会评分、市场型机会判断、完整细分大盘 |
| 看竞对 | 头部、跟随者、新进入者靠什么赢，哪里仍没满足用户？ | 产品力、运营力、需求满足矩阵、竞争壁垒、可攻击缝隙 |
| 看自己 | 对这个品类和机会，我们能不能做、适不适合做？ | 账号背景、品类专属回答、优势、缺口、硬边界、自身适配 |
| 看机会 | 最终有几个可信机会，为什么？ | 0–N 个机会、评分、证据覆盖、推理、反证、人工结论 |

## 5. 目标信息架构

### 项目中心

服务少量深度项目。它负责新建、继续、归档和查看最近结论，不承担复杂的项目组合管理。

项目卡应让用户看见：研究目标、站点、当前阶段、最近业务结论、主要缺口、完成情况和继续研究入口。管理操作降级到“更多”。

### 项目一级页

负责决策总览，而不是重复五个完成度。它应展示：

- 当前一句话判断。
- 需求主线。
- 当前 0–N 个候选或正式机会。
- 五看各自的一句结论、关键证据和缺口。
- 当前唯一推荐动作。

### 五看二级页

每一看都在项目内展开完整分析。页面必须保留项目、研究目标、当前需求和当前选择，不应让用户感觉跳到另一个独立工具。

### 三级详情

原始关键词、评论原文、单个细分市场大盘、单 ASIN Listing/图片/流量/变体、机会证据等通过页内 Tab、抽屉、弹窗或更深一层路由展开。

### 导航原则

- 面包屑体现“项目中心 / 项目 / 五看 / 当前对象”。
- 返回后保留筛选、选择、滚动位置和项目上下文。
- 页面可自由跳转，但系统提供一个基于证据缺口的推荐下一步。
- 上游需求分类变化后，依赖它的下游结论应标记为“需复核”。

## 6. 关键页面定义

### 看用户

首页围绕需求分类，而不是关键词或评论数量。AI 可自动分类，但用户必须能合并、拆分、重命名、排除和确认。确认后的需求分类可直接作为看市场的细分标准。

每类需求至少包含用户画像、场景、JTBD、决策路径、当前替代方案、已满足部分、未满足部分、需求强度和证据可信度。

### 看市场

首页展示各需求细分市场的机会评分。点击细分市场进入独立二级页，完整复用市场大盘能力，并按细分过滤趋势、体量、集中度、价格带、卖家分布、新老品、上架时间、BSR、评分和评论等。

市场评分必须解释依据，并把证据可信度独立展示。样本不足不能直接等同于低机会。

### 看竞对

样本至少覆盖头部、跟随者和新进入者，允许每类多个。核心组件是“需求维度 × 竞品”的满足矩阵。

页面必须同时输出产品力、运营力、目标用户、满足需求、未满足需求、不可复制壁垒、可攻击缝隙，以及“我们可能如何赢”。单 ASIN 的 Listing、主图/A+、流量词、变体矩阵和历史趋势进入详情。

### 看自己

通用背景在账号层维护一次，进入项目自动带入。背景包括团队能力、供应链、预算、类目经验、渠道、内容能力、利润边界、MOQ、合规和风险偏好。

AI 根据当前品类、需求、细分市场和竞品缝隙提出 3–7 个针对性问题，优先使用选择、量化输入和短回答。项目回答不自动覆盖账号通用背景。

### 看机会

AI 综合四看结构化结论生成 0–N 个候选机会。用户可以确认、编辑、合并、删除或重新生成。

机会卡必须展示：机会类型、目标用户、场景/JTBD、未满足需求、当前替代方案、市场依据、竞品缺口、自身适配、风险、分维度评分、证据覆盖度、结论置信度和人工状态。

机会二级页按“结论、证据、推理”组织。证据可以打开原始关键词、评论、图表、ASIN 或项目回答。推理展示结构化的“证据 → 判断 → 结论”、反证、风险与人工修改记录，不展示冗长的模型私有思考文本。

## 7. AI 与 Prompt 原则

### AI 的角色

- AI 负责分类、归纳、提出问题、解释评分、发现跨来源关联和生成候选机会。
- AI 不得虚构缺失数据，不得为了给出答案而强行生成机会。
- 可确定计算的指标使用规则或公式；AI 负责解释，不随意改写原始数值。
- AI 输出必须带证据引用 ID，能回到原始来源。
- 人工修改和 AI 原始判断都应保留，方便审核。

### Prompt 管理中心必须提供的预设

- 看自己·品类引导问题。
- 五看·综合机会识别。
- 机会·反证审查。
- 机会·审核摘要。

所有预设需可查看、编辑、恢复默认并有版本标识。详细输入输出见 Phase 0 PRD。

### 评分原则

机会评分建议综合需求强度、市场机会、竞品缺口、自身适配和证据可信度。每一维必须读取该机会自己的证据，禁止用某个页面的完成百分比直接替代商业质量。

总分之外独立展示证据覆盖度。Phase 0 允许用户修改最终判断，但暂不提供复杂权重编辑器。

## 8. HTML 报告是正式产品输出

报告面向同事和审核者，不是简单打印页面。内容按以下叙事组织：

`研究目标 → 用户需求 → 市场细分 → 竞品缺口 → 自身适配 → 机会结论`

基本要求：

- 可独立打开，样式和关键资源分享后不失效。
- 首页直接展示站点、研究目标、最终结论、机会数量和生成时间。
- 有机会时展示 0–N 张正式机会卡；没有时展示无机会或证据不足的原因。
- 图表只选支持结论的内容，不把所有大盘图无差别塞入报告。
- 每个结论带证据摘要和来源编号，末尾有证据索引与分析口径。
- 区分 AI 原始判断、人工修改与最终确认。
- 桌面阅读和打印均清晰易读。

## 9. UI 设计纲领

### 保持不变的视觉基因

- 靛青到紫色的品牌主色。
- 白色或极浅灰背景、克制渐变、柔和阴影。
- 较大的圆角、充足留白、友好的工具感。
- 清爽、现代、接近消费级产品的体验，不做传统 ERP 风格。

### 必须遵守的排版原则

- 每页只有一个主标题、一句最强结论和一个主操作。
- 先结论，后证据，再原始数据；不要先堆图表。
- 同一业务块最多两层容器，减少卡片套卡片。
- 重要数字必须带业务含义，样本数和完成度只能作为次级信息。
- 关键正文不低于 14px，说明文字不低于 12px。
- 状态不能只依赖颜色；必须同时有文本或图标含义。
- 关键需求、证据和风险不能被永久截断，应允许展开。
- 空状态必须说明原因、缺什么、如何补、补完会得到什么。
- 主按钮位置和含义跨页面保持一致。
- 1024px 宽度下仍需可用；中等宽度避免三列窄卡和 10px 密集标签。

### 推荐内容层级

- H1：当前页面或对象。
- 核心判断：用户此刻最需要读懂的一句话。
- 关键证据：2–5 条可追溯依据。
- 风险/反证：为什么可能不成立。
- 下一步：当前唯一推荐动作。
- 详细数据：按需展开。

## 10. Phase 0 范围

### 必须完成

- 研究目标和站点即可建项。
- 项目内五看完整路径。
- 需求分类驱动细分市场。
- 每个细分市场拥有完整大盘详情。
- 头部、跟随者、新进入者的竞品判断。
- 账号背景自动带入与品类专属提问。
- AI 输出 0–N 个候选机会，支持人工确认和编辑。
- 机会原始证据、结构化推理和反证。
- Prompt 管理中心预设。
- HTML 审核报告。

### 明确不做

- 大批量项目组合管理和复杂驾驶舱。
- 打样、访谈、广告测试等验证任务执行。
- 负责人、截止日期、提醒、实验管理和后续项目排期。
- 复杂的机会评分权重编辑器。
- 为了视觉炫技改变现有 UI 风格。

## 11. 当前实现与目标状态

### 已有基础

- React 19、Vite、TypeScript、Tailwind CSS。
- 市场大盘、市场细分、关键词、VOC、竞品、利润计算等现有工具。

### 仍需重点补齐

- 项目中心仍偏状态管理，尚未围绕最近业务结论组织。
- 项目概览仍偏完成度，尚未成为决策总览。
- 五看与全局工具仍有上下文割裂和重复页面。
- 需求分类尚未完整成为所有后续页面的统一索引。
- 看市场尚未完整实现“一细分一套完整大盘详情”。
- 看自己尚未完成账号背景自动带入与动态品类问题。
- 看机会当前以读取展示为主，候选确认、编辑、AI 综合判断、证据推理仍需补齐。
- HTML 审核报告尚需按决策叙事重做。

## 13. 数据与配置

主要数据来源包括 Excel/CSV、卖家精灵 MCP、可选的领星能力，以及 AI 模型。没有密钥时应尽量允许通过演示数据理解产品；真实分析前必须提前告知缺少的数据或配置会影响哪些结论。

账号、密钥和项目数据目前包含浏览器本地存储与可选云同步。任何后续改动都不得把敏感密钥写入仓库或报告。

## 14. 后续 AI 的工作规则

在修改产品前，后续 AI 必须：

1. 先读本文，再读 Phase 0 PRD和相关实现文件。
2. 明确区分“当前实现”“目标状态”和“本次授权范围”。
3. 优先补齐从未满足需求到机会结论的闭环，不继续堆孤立图表。
4. 保持现有视觉风格，UI 改动以层级、排版、可读性和操作主次为主。
5. 新增结论必须有真实证据来源；AI 输出必须允许追溯和人工修改。
6. 不把证据不足写成无机会，不强制生成至少一个机会。
7. 不擅自加入 Phase 0 已排除的任务执行、提醒或复杂项目管理能力。
8. 尽量复用现有市场、关键词、VOC、竞品、利润和 Prompt 能力。
9. 完成改动后运行 `npm test`、`npm run lint` 和 `npm run build`，并说明验证结果。
10. 若改变产品定义、业务规则、页面职责或 Phase 0 边界，同步更新本文和 Phase 0 PRD。

## 15. 决策优先级

发生冲突时按以下顺序判断：

1. 用户在当前任务中的明确要求。
2. 本产品总纲中的核心目标、机会定义和范围边界。
3. Phase 0 业务与 UI 优化 PRD。
4. 现有 UI 与数据模型的一致性。
5. 工程便利性。

工程实现服务于机会判断，不应为了复用旧页面而牺牲业务主线。
