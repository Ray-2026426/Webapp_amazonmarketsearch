# 定价与订阅实验设计（M6 · Phase B 蓝本）

> **范围声明（重要）**：本文只是**设计与实验方案**，本轮**不接支付、不做计费拦截**。
> 现在的用量记账（`usage_events`）已经按 `workspace × 工具 × 次数` 记录，足以支撑下面所有口径的核算；
> 真正收钱之前，需要先跑完实验、确认付费意愿，再决定接入哪家支付。

---

## 1. 计量口径（直接复用现有实现）

| 维度 | 口径 | 现状 |
| --- | --- | --- |
| 记账单位 | 一次数据池事件（含成功/失败/缓存命中） | ✅ `usage_events` 已记录 |
| 外部调用次数 | `calls`（一次业务动作可能打多次接口） | ✅ 已记录 |
| AI 用量 | `input_tokens` / `output_tokens` | ✅ 已记录（AI 事件） |
| 成本估算 | MCP 单次 + LLM 每百万 token（成本表可配） | ✅ `usageAccounting.estimateEventCost` |
| 缓存降本 | 命中事件按 0 计费，并单独统计"省下的钱" | ✅ `savedUsd` |
| 配额 | 只计实际计费事件（缓存命中不占额度） | ✅ `checkQuota` |
| 归属 | `workspace_id` / `user_id` / `project_id` | ✅ 三列都有索引 |

**为什么按"外部调用 + token"而不是"项目数"计费**：项目数不反映成本，而数据池成本几乎完全由这两项驱动；
按它们计费才能做到"用多少付多少"，也避免用户为省配额而把多个项目塞进一个。

## 2. 套餐分层（待实验验证，不是最终定价）

| | 体验版（免费） | 标准版（推荐） | 团队版 |
| --- | --- | --- | --- |
| 定位 | 试用与教学 | 单人/小团队做真实选品 | 多人协作 + 管理 |
| 月配额（外部调用） | 200 | 3,000 | 10,000 |
| AI token | 按调用计入配额 | 含，超出按量 | 含，超出按量 |
| 项目数 | 3 | 不限 | 不限 |
| 团队空间/权限 | ✖ | ✖ | ✅（owner/admin/member/viewer） |
| 管理员后台 | ✖ | ✖ | ✅（用量/审计/配置） |
| 导出 | HTML | HTML + MD | HTML + MD + 批量 |
| 支持 | 文档 | 文档 + 邮件 | 文档 + 邮件 + 专人 |

> 配额的"单位"就是上表的"外部调用次数"，与 `usage_events.calls` 一一对应——**不要另造一套单位**，
> 否则账算不平（这是很多工具类产品踩过的坑）。

## 3. 实验设计（先验证意愿，再定价）

### 实验 1：配额感知（2 周，零成本）
- **假设**：让用户看见自己的用量与成本，会显著降低无效抓取（重复抓同一 ASIN）。
- **做法**：管理员后台的用量面板对**所有用户**开放（现在只有管理员能看全量，普通用户可通过 `/api/data/usage` 看自己的）；
- **度量**：人均外部调用次数、缓存命中率、（同一 ASIN 的）重复抓取率；
- **成功标准**：缓存命中率上升 ≥10 个百分点 或 重复抓取率下降 ≥20%。

### 实验 2：配额上限（2 周）
- **假设**：给免费用户 200 次/月，能筛出真正的付费意向用户，而不会把新手劝退。
- **做法**：免费套餐设 200 次上限，超额时给明确提示与升级入口（**先只做提示，不做支付**）；
- **度量**：超额用户占比、超额后 7 日留存、主动咨询升级的比例；
- **成功标准**：超额用户中 ≥15% 主动咨询或明确表达付费意愿。

### 实验 3：决策包付费点（4 周）
- **假设**：用户愿意为"可直接交管理层的决策包"（HTML/MD 审核件 + 控制点）付费，而不是为"看数据"付费。
- **做法**：免费版导出带页脚水印、不含路线图/控制点；标准版导出完整；
- **度量**：导出行为占比、导出后 14 日内复购/续用行为、访谈中"最舍不得失去的功能"排序；
- **成功标准**：访谈中"决策包"进入前二的用户 ≥50%。

## 4. 定价心理与红线

1. **不要让用户算不清**：配额单位只有一个（外部调用次数）；
2. **不要按席位收小团队的钱**：小团队的实际痛点是成本与协作，不是席位数（团队版按配额分层更自然）；
3. **红线**：任何套餐都不能让"零机会结论"变成付费项——**判断没机会也必须有价值**，否则会诱导用户往"看起来有机会"的地方投钱，直接违背产品北极星；
4. **成本护栏**：单 workspace 月度成本超过套餐价的 40% 时触发人工复核（成本表与用量面板已能算出这个数）。

## 5. 何时接支付（前置条件）

- [ ] 实验 1/2 至少一个达到成功标准；
- [ ] 有 ≥3 个真实团队按周使用（不是一次性试用）；
- [ ] 数据池成本连续 2 个月可预测（月度波动 <30%）；
- [ ] 上线检查清单里的权限/密钥/审计项全部通过（见 `M6-launch-checklist.md`）。
