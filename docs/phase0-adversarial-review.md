# Phase 0 对抗式审查记录

日期：2026-08-30
分支：`phase-0`

## 审查目标

本审查不是确认“页面能编译”，而是主动寻找会让用户错误立项、无法完成 30 分钟流程、误把缺数据当机会、或无法向同事解释结论的问题。

## 需求—实现—证据矩阵

| 业务要求 | 实现证据 | 反向检查 |
| --- | --- | --- |
| 新建项目只需研究目标和站点 | `ProjectCenter.tsx` 的建项表单及默认项目名 | 缺任一必填时不能创建；创建后卡片置顶并从看用户开始 |
| 少量深度项目中心 | 宽卡、最近结论、最大缺口、唯一继续动作；管理操作收入更多菜单 | 删除了未使用的“五看总览/今日建议”驾驶舱代码 |
| 看用户形成需求分类主线 | `UserLookView.tsx` 支持 AI 生成、手工新增、改名、拆分、合并、删除、选择细分标准 | 未选择细分标准时看用户不能完成；下游明确提示缺口 |
| 看市场必须关联需求与细分 | `MarketLookView.tsx` 的需求关联选择、细分评分与 AI 细分结论 | 没有关联需求或目标细分时按钮禁用，进度不能完成 |
| 每个细分复用完整大盘 | 细分页包含 KPI、趋势、季节性、集中度、机会扫描、品牌、价格、评分、卖家、新老品、BSR 与 ASIN 表 | 没有 ASIN→细分映射时明确标为全市场回退，不能伪装成细分证据 |
| 看竞对覆盖三类角色及如何赢 | 头部/跟随者/新进入者、目标用户、产品力、运营力、需求满足矩阵、壁垒、取胜策略 | 需求矩阵和取胜策略未填写时进度不能完成 |
| 看自己复用账号背景 | `SelfAssessmentView.tsx` 自动读取只读背景，AI 生成 3–7 个品类问题 | 不重复要求填写通用 50 项表；问题答案按优势/缺口/边界/适配归类 |
| 机会允许为 0–N | `OpportunityLookView.tsx` 和独立 `OpportunityConclusion` | 明确区分 `no_opportunity` 与 `insufficient_evidence`；零机会需人工确认才算完成 |
| AI 不能直接成为正式结论 | 候选默认 `ai_candidate`，用户可确认、编辑、合并、删除、重生成 | 重生成保留已确认机会；若 AI 本次返回 0，不会静默删除人工结论 |
| 评分读取机会自己的证据 | `scoreOpportunity` 的 25/25/25/15/10 规则与证据覆盖度 | 测试证明即使四看页面全部完成，未绑定证据的机会仍只有低分 |
| 证据、推理、反证可审核 | 机会详情分区展示原始证据摘要、结构化推理、反证、缺失证据、人工修改 | 不展示模型私有思考；无证据时明确提示“暂无记录不代表不存在” |
| 四个 Prompt 可维护 | `AiPromptManager.tsx` 中四个 `phase0-v1` 预设 | 测试断言 ID 与版本均存在；沿用现有编辑和恢复默认能力 |
| HTML 可独立审核 | `opportunityHtmlReport.ts` 生成内嵌 CSS、评分可视化、五看叙事、人工状态和反证 | 全部动态文本进行 HTML 转义；桌面、窄屏和打印均有样式 |
| 上游变化不能静默污染下游 | `applyLookProgressUpdate` 的链式依赖失效 | 看用户更新使已开始的市场、竞对、自己、机会全部变为“需复核”；未开始页面不会被伪标过期 |
| Phase 0 不做执行管理 | 项目五看与机会 UI 中没有负责人、截止日期、提醒、验证任务 | 搜索项目核心页面确认无上述执行控件 |

## 主动攻击过的失败场景

1. **市场很大但没有用户/竞对证据**：机会评分不会因页面完成度自动升高。
2. **AI 被要求必须给机会**：Prompt 明确允许空数组，存储和 UI 支持无机会及证据不足。
3. **人工确认后重新生成**：人工结论保留，并提示 AI 本次未识别到新机会，避免静默覆盖。
4. **修改需求分类后继续看旧结论**：所有已开始的下游视角被标记需复核。
5. **旧 IndexedDB 数据缺少新字段**：需求、竞对、看自己和机会读取时补默认值，不因 `undefined` 崩溃。
6. **恶意文本进入 HTML 报告**：`<script>`、引号和 `&` 被转义；自动化测试覆盖脚本注入样例。
7. **细分没有商品映射**：二级页明确显示全市场回退警告，不把全市场数字冒充细分数字。
8. **1024px 宽度**：项目卡转单列，竞对矩阵横向滚动，机会详情与报告评分转为更少列，关键正文不做永久截断。

## 外部条件边界

真实 AI 文本质量与在线 ASIN/关键词/评论抓取依赖用户自己的 API Key、网络和第三方服务状态。代码在缺少配置时返回明确错误，不会伪造结论；这类外部服务不能由离线自动化测试证明可用。上线后应使用一组脱敏真实品类数据做 30 分钟计时可用性测试，并持续观察 AI JSON 解析失败率与证据引用命中率。
